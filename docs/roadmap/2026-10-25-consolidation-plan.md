## 0. 四个问题的答案

1. **不充值 OpenAI 能不能往下做？** 大部分能。Shuyu 实测目录 57 档 = 39 档图片 + 18 档视频，
   **没有文本模型、没有语音**。所以：
   - **改走 Shuyu**（本轮做）：所有出图——周计划的图文帖与轮播、落地页视觉、模板样片的产品参考图。
     视频、故事板、产品图本来就在 Shuyu。
   - **仍需 OpenAI**：写脚本 / 排计划（现在走兜底模板，质量撑不起收费）、实拍线路（拆段 + 配音）、
     视觉质检、配音 TTS、Logo 生成。充 US$20 足够试点期用。没充之前，这些入口**提前如实标注不可用**，
     不再让客户提交后撞墙（§2 C4）。
2. **邮件提醒（Resend）怎么开？** 步骤见 `docs/ops/resend-email-setup.md`。对外联系邮箱已统一为
   `lucas@sunnyshutter.ca`（`src/lib/config/contact.ts`），试点申请提醒默认发到这里。
3. **视频生产够稳了吗？** 链路功能完整、单次真机全通，**但没在量上证明过**（§1）。
4. **下一步怎么走？** 先做本轮整合（出口标准见 §5），再拿 1–3 个真实试点商家跑 30 天，
   用询盘数据决定 CEO V2 brief（增长 Agent）里先做哪几件。方向不变，先把地基补齐。

## 1. 视频生产稳定性：数据怎么说

生产库 90 天（只读统计，`tmp/stability/`）：

| 周 | Shuyu 视频 成功 / 失败 | 故事板帧 成功 / 失败 | 批次 完成 / 失败 | 发生了什么 |
|---|---|---|---|---|
| 07-19 | 15 / 1 | 11 / 1 | 5 / 87 | 内部超管账号自动化批量，Shuyu 图片套餐轮换（假停机） |
| 07-26 | 0 / 5 | 17 / 32 | 0 / 5 | 合作方拒单（PROVIDER_REJECTED 29） |
| 08-02 | 42 / 63 | 372 / 55 | 41 / 69 | 模板库扩容 + 0804 视频套餐下架（已根治：多套餐 + 提交级降级） |
| 09-13 | 2 / 0 | 5 / 0 | — | 零星使用 |
| 10-18 | 5 / 0 | 32 / 11（9 条是取消） | 1 / 0 | 1025 真机验收 |

结论：
- 失败几乎全部集中在两次供应商漂移事故周，且多为内部自动化跑量；两次的根因都已修。
- **8 月之后没有真实量**（60 天约 12 条），所以「稳定」没有被证明，只是没被否定。
- 供应商「提交确认未知」稳定在故事板帧的 7–9%，现在单条与批量两条路都能自愈。
- 结构性风险（本周 3 个生产 bug 都出自这里）：
  1. **合成有两套实现**：应用内（`stitch-service`）与生产 GitHub runner（`scripts/stitch-runner.ts`），
     字体、混音、组装计划各写一遍——中文字幕方框、实拍口播被音乐替换都只发生在 runner。
  2. **健康探针测的不是生产路径**：`/api/health/media` 在 Vercel 上合成，生产成片却在 runner 上合成。
  3. **文本能力静默降级**：OpenAI 不可用时脚本、计划悄悄换成模板，客户不知道。
  4. **单一供应商**：火山欠费、BytePlus 未配，Shuyu 是唯一视频线。

## 2. 工作流

### C1 访客到上手只有一条主线（产品 + 设计）

现状两条漏斗承诺相反：落地页卖「上门服务商的 30 天陪跑试点」、页面上没有注册入口；自助注册只能从
登录页进，进来是电商自助出片台（默认批量 10 条，试用额度只有 3 条）。核心价值（询盘页）锁在管理员手里、
没有申请按钮。设计：

1. **落地页 `/`**（Persuade；交易所风格，媒体承担彩色）：
   - 英雄区：Shuyu 生成的上门服务场景（夜景客厅、新装厨房、庭院、手机亮起询盘）静帧 + 1080P 动态循环；
     标题沿用「先试 30 天：内容我们来做，询盘你来数。」；**双入口**：主按钮「免费试做 3 条」→ 注册，
     次按钮「申请陪跑试点」→ 申请表。
   - 「一周会发生什么」：周计划 → 视频 → 询盘页 → 渠道追踪链接 → 询盘进来、被数清——用真实产品界面截图。
   - 真实交付：SunnyShutter（关联方，明确标注）的窗饰成片与询盘页——上门服务的真证据，替换电商样片。
   - 规则写在前面、申请表保留。
2. **注册**：邮箱、密码、店名、行业（上门服务品类）、城市、条款同意勾选；中英文错误文案。
3. **上手向导 `/app/welcome`**（4 步，每步都有看得见的产出）：
   ① 你的生意（一句话 / 网址，预填注册信息）→ ② 品牌（logo、主色、联系方式 → 默认品牌包 + 尾卡预览）
   → ③ 第一条视频（按行业推荐 3 个有真机样片的模板 + 上传作品照片 → 故事板）
   → ④ 询盘页（用前两步生成预览 +「申请开通」→ 提醒创始人）。完成后进 `/app` 的「第一周清单」。
4. **修掉的摩擦**：额度 3 条与批量默认 10 条冲突（按剩余额度钳制、显示段数上限）；额度用完的去处
   （申请试点 / 联系我们，不再指向已下线的账单页）；询盘页「申请开通」按钮；周计划的视频帖一键带脚本去创作；
   创作页「没有品牌包」给链接；登录页主按钮是登录；`/persona` 去掉宠物投资人演示链接；
   成品库样片与状态栏「不含示例数据」口径一致；密码找回（发信依赖 Resend，未配时给联系邮箱）。

### C2 出图全部走 Shuyu

按审计设计：新表 `ContentPostImageTask`（照 `StoryboardFrame` 的形状，一张图一行），异步提交 + cron 轮询 +
读时对账；渲染锁沿用 `renderStartedAt`、接管前须无在途任务；单张成功立即落到帖子（行锁合并）；部分失败
保留已出的图、可补齐；取消停未提交的、在途的照收；1K 起、按画幅过滤套餐；`CONTENT_POST_IMAGE_PROVIDER`
开关默认 shuyu，OpenAI 同步路径保留到单独的删除 PR。真机验收 ≤250 点（一张单图 + 一组轮播）。

### C3 合成只留一套实现

- 把拼接、后期（字幕 / 混音 / 字体）、缩略图抽成一个纯模块（`src/lib/media/compose/`），应用内与 runner
  都只调它；runner 只剩下载、上传、回调。对拍测试保证同输入同输出。
- 生产金丝雀：每日 GitHub workflow 用固定素材跑一次真实 runner 合成（中文字幕 + 口播 + 背景音乐），
  断言选中打包字体、人声在、时长对；失败即告警。

### C4 能力状态一处说清

能力注册表（文本、视觉、出图、视频、配音、审核、图库、网页抓取、邮件），由 `capability-probe` cron 实测；
界面按状态置灰并说人话（例如「写脚本暂用模板生成，AI 写作恢复后自动启用」），OpenAI 恢复后自动亮起。

### C5 视频压测 + 14 个模板补样片

14 个没有真机样片的模板走客户同一条批量管线出片（产品参考图改用 Shuyu 出），分波 6 个；
记录首轮成片率、自愈次数、合成、字幕与口播；人工过检后进样片白名单。顺带证明「量上的稳定」。
出口：首轮成片率 ≥ 90%（含自动自愈），零人工介入。预算约 20k 点。

### C6 其余不足

见缺口清单审计（并入本节）。

## 3. 顺序与预算

1. C2 出图迁移（解锁周计划的图文）→ 2. C5 压测与样片（挂在生产 cron 上跑，期间做别的）→
3. C3 合成单一实现 + 金丝雀 → 4. C4 能力注册表 → 5. C1 旅程（落地页视觉、注册、上手、摩擦）→ 6. C6。

Shuyu 余额约 38,000 点：落地页视觉约 6,000；样片 + 压测约 20,000；图文验收 ≤ 250；
**至少留 10,000 给首批试点客户**。每批付费提交前核对余额。

## 5. 本轮完成的定义

- 访客能从首页一路走到「第一条成片 + 询盘页预览」，中途不遇到死胡同或与承诺矛盾的界面。
- 每个入口要么端到端可用，要么提前如实标注不可用；没有「提交后才失败」。
- 合成只有一套实现，金丝雀每天在生产 runner 上验证字体与人声。
- 14 个模板补齐真机样片；压测首轮成片率 ≥ 90%。
- 周计划的图文帖能用 Shuyu 出图并交付。
- typecheck、lint、全量测试全绿；生产部署成功；验收记录与 artifact 更新。
