## 0. 战略取舍（本轮最重要的一条）

**我们不做投放数据分析，也不做赛马择优。**

理由：TikTok / 小红书 / YouTube 自带曝光、完播、转化的原生看板，商家每天都在看。
我们在别人主场做一套更弱的数据分析，既拿不到全量数据，也说服不了用户改变习惯。

**我们做的是：把电商商家从「有商品」到「有一整套可投的素材」这条流水线，跑得比谁都快、比谁都便宜、比谁都稳。**

因此本轮的竞争力定义为三个可测的数字，而不是功能条数：

| 维度 | 指标 | 现状 | 本轮目标 |
|---|---|---|---|
| 成本 | 单条合格成片的全链路 token + 供应商成本 | 未持续度量 | 建立度量，并降低 ≥30% |
| 速度 | 从「贴商品链接」到「第一条可用成片」的 P50 | 无此入口 | ≤ 8 分钟 |
| 质量 | 首次生成即被用户接受的比例（一次通过率） | 未度量 | 建立度量，≥ 60% |

功能取舍原则：**能用成熟开源工作流 / 已验证的同行做法解决的，一律直接复用，不自研。**

### 赛马与投放模块的处置

- 从主导航移除 `/app/racing` 入口，功能不删除、数据不迁移，降级为内部只读归档。
- `racing-service` / `scoring-service` / `sweep-service` / `business-metrics-import` 停止新增投入。
- 保留 `publish-service` 中与「导出/发布素材」相关的部分（属于电商工作流），剥离与「效果评估」相关的部分。
- 验收：主导航不再出现赛马；现有数据可通过 internal 路径查看；相关测试改为归档态断言。

## 1. 主线一：电商工作流复现

### E1 · 商品链接起片（P0，本轮核心）

**用户故事**：我是电商商家，把商品详情页链接贴进来，几分钟后拿到一组可投的产品图和短视频。

**流程**

```
商品 URL
  → 抓取（标题 / 卖点 / 价格 / 主图组 / 规格）
  → 结构化商品档案（SKU Profile）
  → 自动填充：产品图工作台 + 创作描述 + 品牌包
  → 故事板 → 成片
```

**范围**

- 支持来源：Shopify、Amazon、独立站通用 OG/JSON-LD、淘宝/天猫（尽力而为，失败可手工补）。
- 抓取失败必须优雅降级为「手工上传 + 手工描述」，不能把用户堵死在入口。
- 抓到的图先过一遍产品图工作台的现有优化线路（保持产品一致性硬约束）。
- 复用：`selling-point-service`（卖点抽取）、`product-image-service`、`storyboard-service` 全部现成。
  新增的只有抓取层与 SKU Profile 的持久化。

**验收标准**

1. 贴入一个 Shopify 商品链接，无需任何额外输入即可进入故事板环节。
2. 抓取结果对用户完全可见可编辑（标题、卖点、选中的图），不是黑盒。
3. 抓取失败时给出明确原因与手工路径，不消耗积分。
4. P50 从贴链接到第一条成片 ≤ 8 分钟。

**不做**：不做竞品广告库、不做爬取他人广告素材。

---

### E2 · 统一素材库与 SKU 素材包（P0）

**问题**：产品图只在工作台底部有「最近产品图」，成品库只装视频，文案却写「已进入素材库」——
用户找不到自己的东西，图和片是两个割裂的世界。（本次已先把文案改成不撒谎，功能仍缺。）

**范围**

- 一个素材库，收纳：上传原图、生成产品图、故事板分镜、成片、字幕/导出件。
- 以 **SKU 为组织单位**：一个商品下挂它的全部素材，而不是按时间倒序的一锅粥。
- 每个资产统一支持：预览、下载、继续编辑、送进单条/批量视频生产。
- 与 E1 打通：链接起片自动创建 SKU 并归档全部产物。

**验收标准**

1. 任意生成物在生成后 5 秒内出现在素材库对应 SKU 下。
2. 下载对所有资产类型可用（图/视频/字幕），跨域托管也必须真下载而不是打开新页。
3. 「成品库」与「产品图库」合并为一个入口，导航不再有两个近义词。

---

### E3 · 多平台规格与一键导出（P1）

**范围**

- 输出预设：TikTok / Reels / Shorts（9:16）、小红书（3:4 + 9:16）、商品主图（1:1）、详情页横版（16:9）。
- 一个 SKU 一键导出「投放素材包」：多规格视频 + 主图 + 字幕 SRT + 文案，打包 zip。
- Shopify 商品图回写（选做，需商家授权）。

**验收标准**：一次导出得到可直接上传各平台的文件，无需二次裁剪。

**不做**：不做代投放、不做账号托管发布（合规与账号风险不成比例）。

---

### E4 · 目录级批量（P1）

**范围**：从「一次一个 SKU」升级到「一次一批 SKU」——上传 CSV / 连接店铺 → 批量起片。
沿用现有批量生产的队列、熔断、退款与恢复机制，只是把输入维度从模板换成 SKU 列表。

**验收标准**：50 个 SKU 的批次可提交、可暂停、可逐条取消、失败不重复计费。

## 2. 主线二：成本 / 速度 / 质量工程

这条线不产出新页面，但它才是护城河本身。

### C1 · 路由成本与速度可观测，并据此自动选路（P0）

**现状**：`video-route-registry` 已有多条线路（byteplus / shuyu / mock），
但选路靠配置与人工判断，没有成本与耗时的持续画像；供应商漂移（0728 套餐 ID 轮换、
1K 下线、0729 视频线路崩溃）只能靠事故暴露。

**范围**

- 每次生成记录：线路、模型、分辨率、时长、实际耗时、实际成本、成功/失败/退款。
- 生成线路健康画像（成功率、P50/P95 耗时、单条成本），驱动默认选路。
- **能力探测**而不只是存活探测：定期校验套餐 ID、支持的分辨率与音频能力，漂移即告警并自动降级。
- 用户侧只看到一句话：当前线路 / 预计耗时 / 预计消耗，以及线路不可用时的替代方案。

**验收标准**

1. 任一线路连续失败达阈值，新任务自动切换到可用线路，用户无感或仅收到一次提示。
2. 后台可回答：「上周每条成片平均花了多少钱、多少分钟」。
3. 供应商接口漂移能在事故前被探测到。

### C2 · 定价不惩罚迭代（P0，产品与工程共同项）

调研结论：**用户流失的头号原因不是质量差，而是积分模型惩罚正常使用**
（有用户 15 分钟烧完额度当天退订）。

**规则**

1. 失败、被安全拦截、供应商退款的任务，**一律不计费**，且在界面上明说。
2. 迭代阶段（故事板改帧、产品图换构图）**显著低于**最终出片的价格。
3. 「取消这一轮」永远免费。
4. 价格页必须能回答「我一个月大概花多少钱」，而不是只给一个积分数。

**验收标准**：任意失败路径的账单增量为 0，且有回归测试覆盖；用户可在生成前看到预计消耗。

### C3 · 一次通过率（P1）

- 把 SunnyShutter v2 已验证的锁（故事板抽卡择优、主体锁、防幻视、裁尾）**通用化**为可配置的品类锁。
- 度量「首次生成即被接受」的比例，作为质量北极星。
- 复用现成开源工作流与提示词体系，不自己发明镜头语言。

## 2.5 主线三：产品 LOGO 的定型与植入（P0，本轮新增）

### 问题

「产品 LOGO 怎么定型、怎么加进去」其实是**两个不同的问题**，我们现在把它们混成了一个，
而且两个都只做了最低档的解法：

| | 问题 | 现状做法 | 为什么僵硬 |
|---|---|---|---|
| **定型** | 产品自身的 logo（印在瓶身/包装/吊牌上）在生成时会走形、乱码、颜色漂移 | 只靠提示词约束 + SunnyShutter 专属硬编码锁 | 提示词管不住像素；换个客户就要重写一套 profile |
| **植入** | 品牌 logo 要出现在成片里 | ffmpeg 把 PNG 固定叠在画面角落 + 片尾独立品牌卡 | logo 不在产品上、不随镜头运动、不受画面光照 —— 看起来是「一条加了水印的 AI 视频」，不是「这个品牌的广告」 |

`brand-overlay-renderer` 的注释其实已经写明了原因：AI 供应商对精确文字/logo/®/细线条的
还原不稳，所以「唯一可靠的方案」是自己在合成层叠上去。这个判断在 2026 年只对了一半 ——
它对**画面里的品牌标识**成立，但**产品自带的 logo** 早就有更好的解法了。

### 市场上做得最好的做法（调研结论）

产品图/产品视频这个赛道已经收敛出一个共识：**product-first，不是 prompt-first。**

同行把产品植入分成三档，差别就在「产品像素有没有被重画」：

1. **纯提示词生成整图** —— 模型会重新诠释产品而不是保留它：颜色偏移、材质被抹平、
   **logo 变得不可辨认**。这是我们目前生成模式的档次。
2. **模板/预设合成** —— 快，但整个赛道共用同一批场景，且模板光线经常和产品原本的光冲突。
3. **参考图锚定（reference-based）** —— 锁住产品像素，只生成它周围的环境；
   于是**真实的 logo 是「带过去」的，而不是被逐个字符重画的**。做电商目录的都用这一档。

品牌 logo 的植入同理分档：静态角标水印是最低档（在投放语境里甚至会损害可信度，
专业工具都在强调无水印导出）；进阶做法是**把 logo 作为参考图投进场景**，
或用**平面跟踪（planar tracking）把 logo 贴到画面中的真实平面上并随镜头运动**——
跟踪的是一个平面的位置、旋转、缩放与透视，所以贴上去的东西看起来是「印在那儿的」。

视频侧的一致性则靠**视觉锚点**：把品牌摄影、产品渲染图作为参考图喂进去，
锁住 logo 位置与配色，而不是每次重写提示词碰运气。

### 我们要做的

**B1 · 产品身份锚定（替换「靠提示词管 logo」）**
- 生成走参考图锚定路线：产品像素来自用户上传的真实产品图，模型只负责生成环境、光线、镜头。
- 产品区域出问题时用**局部重绘**修，而不是整图重生成 —— 不重画就不会糊。
- 验收：同一产品跨 10 次生成，logo 可辨认率 100%，无字符错乱。

**B2 · 品牌植入分三档，由用户选，而不是一刀切**
| 档位 | 做法 | 适用 |
|---|---|---|
| 自然植入 | logo 来自产品参考图，天然长在产品/包装上 | 默认；最像真广告 |
| 平面跟踪贴合 | logo 贴到画面中的平面（墙面、屏幕、包装面）并随镜头运动 | 需要强曝光品牌标识时 |
| 角标 / 尾卡 | 现有 ffmpeg 合成层 | 保底档，供应商不给力或用户明确要水印时 |

关键改动：**现状那一档从「唯一做法」降级为「保底档」**，且默认不再是它。

**B3 · 品牌包升级成 Brand Kit**
现在的品牌包 = 一个 logo PNG + 一张尾卡。要补齐同行标配：色板、字体、logo 安全区与最小尺寸、
禁用变形规则，以及**可复用的构图（framing / 角度 / 产品位置）与摄影风格（光线 / 相机质感 / 氛围）**。
后两者是同行做目录级一致性的核心：一次定好，整个 SKU 目录复用，而不是每条重写提示词。

**B4 · 客户锁通用化**
`sunnyshutter-brand-pack` / `client-lock-profiles` 目前是给单一客户硬编码的。
改成按品类配置的锁模板（窗帘、服饰、食品、3C…），新客户选品类而不是等我们写代码。

**B5 · 出片前自动校验 logo**
成片交付前自动检查 logo 区域的可辨认度与畸变，不合格**自动重出**，
而不是等用户看到糊掉的 logo 再来投诉。这条直接喂 C3 的一次通过率指标。

### 复现方案：三层管线

同行的做法拆开看只有一句话：**产品像素不重画，只生成它周围的东西，然后验一遍。**
落成三层，每层都对应我们已有或缺失的具体零件。

```
用户产品图
  │
  ├─ 第 0 层 · 锚点  抠图 → RGBA + mask + logo 区域框     ← 现在完全没有
  │
  ├─ 第 1 层 · 生成  只画 mask 之外的环境                  ← 现在是整图重绘
  │
  └─ 第 2 层 · 校验  比对 logo 区域，不合格自动重出        ← 现在完全没有
```

#### 第 0 层 · 产品锚点（Product Anchor）

一个 SKU 一次性产出、之后所有图与视频复用的资产：

| 产出 | 用途 | 怎么来 |
|---|---|---|
| 产品 RGBA 切片 | 合成时贴回去的真实像素 | 抠图 |
| 产品 mask | 告诉模型「这块不许画」 | 抠图的 alpha 通道 |
| logo 区域框（bbox） | 校验层要知道去哪儿看 | 用户在锚点上框一次；或用品牌 logo 资产做模板匹配自动定位 |

**现状差距（必须先补）**：`src/lib/providers/remove-bg.ts` 是个**空壳** ——
没有 `REMOVE_BG_API_KEY` 就原样返回，有 key 也只是 `// V2: 真实抠图 API 调用` 的 TODO。
整条锚定路线的地基就卡在这里。选型上抠图是成熟商品，不自研模型：
商用 API（remove.bg / Clipdrop）或自建开源分割模型（SAM / BiRefNet）二选一，
按成本与出图量决定 —— 这正是 C1 那把尺子该回答的问题。

logo 区域框优先走「用户框一次」：一次性人工换来 100% 可靠的校验基准，
比自动检测省事得多，而且一个 SKU 只做一次。

#### 第 1 层 · 只生成环境，不重画产品

按供应商能力分三条路径，**优先级从上到下**：

**路径 A · 带 mask 的编辑（首选）**
把 mask 传给图像编辑接口，模型只在产品之外作画，产品像素**零重画** → logo 天然 100% 保真。

我们其实离这条路只差一个参数：`src/lib/providers/openai-image.ts` 的
`composeReferenceImage` 已经在用 `images.edit` 多图参考，但**没有传 mask**，
所以它的注释老老实实写着「在保持主体一致的前提下**重绘整图**」。
重绘整图 = logo 交给模型逐字符重画 = 糊。加 mask 参数 + 第 0 层的 mask 就能改档。

**路径 B · 生成场景后合成回去（供应商不支持 mask 时）**
模型自由生成环境 → 把锚点 RGBA 贴回原位 → 匹配光影（阴影方向、色温、接触阴影）。
产品像素同样零重画，代价是合成痕迹要靠光影匹配抹平。
Shuyu 的 image2 线路目前没有 mask 能力，走这条。

**路径 C · 提示词约束（保底，即现状）**
`buildProductImagePrompt` 里那段
"Preserve the exact product identity... logo, label placement..." 是**提示词级**保护，
模型仍在重绘整图。留作兜底档，不再是默认。

三条路径的选择由线路能力决定，和 C1 的能力探测同一套机制 ——
探测到某条线路支持 mask，就自动升到路径 A。

#### 第 2 层 · logo 保真校验（Gate）

拿第 0 层的 bbox 去生成结果里取同一块，和品牌 logo 资产比三个判据：

| 判据 | 抓什么问题 | 手段 |
|---|---|---|
| 结构相似度 | 字符走形、笔画断裂 | SSIM / 特征点匹配（ORB）对齐后比对 |
| 文字可读性 | 乱码、多字少字 | OCR 结果与品牌名做字符串距离 |
| 色彩偏移 | 品牌色漂移 | 主色 ΔE 与 Brand Kit 色板比 |

任一判据不过 → **自动重出**（先原路径重试，连续失败则降档到路径 B 的合成），
不合格的成片不进交付。这条同时产出 C3 的一次通过率指标 —— 校验通过率就是它。

#### 视频侧怎么接

1. **首帧锚定**：i2v 的首帧用第 1 层产出、且已过第 2 层校验的产品图。
   logo 从首帧带进视频，而不是让视频模型自己画。
2. **抽帧复检**：对成片抽样若干帧跑第 2 层；漂移超阈值就重出该镜头，而不是整条重来。
3. **平面跟踪贴合（B2 档 2）**：逐帧解算目标平面的单应矩阵（homography），
   把 logo 按透视贴上去。用开源 CV 能力 + ffmpeg 透视滤镜实现，不引入专有软件。
   落点是 `src/lib/video-generation/brand-overlay-renderer.ts` 新增一种模式，
   现有的固定角标模式原样保留为保底档。

#### Brand Kit 的两个可复用配方

同行做目录级一致性靠的不是每条重写提示词，而是从一张参考图里抽出两样东西存起来复用：

- **Composition**：构图、机位角度、产品在画面里的位置
- **Photography Style**：光线、相机质感、氛围、色调

一个 SKU 目录定一次，后面所有图和片都套同一份 —— 这也是 B3 里最值钱的部分，
比色板字体更能决定「看起来是不是同一个品牌」。

#### 实施顺序（依赖关系是硬的）

```
抠图能力（补 remove-bg 空壳）
      ↓
产品锚点资产（RGBA + mask + bbox）
      ↓
路径 A / B 生成  ──→  logo 校验 Gate  ──→  首帧锚定进视频
      ↓                                        ↓
   Brand Kit 配方                        平面跟踪贴合
```

前两步没做完，后面全部无从谈起 —— 所以 M2 的第一件事是抠图，不是模型调优。

### 验收标准

1. 用户上传一张带 logo 的产品图，生成的图与视频里 logo 始终可辨认、不变形、颜色不漂。
2. 同一 SKU 跨 10 次生成，第 2 层校验通过率 100%（这是可自动化测的，不靠人眼）。
3. 品牌植入档位可选，默认不是角标水印。
4. 新客户接入不需要写代码：选品类锁 + 填 Brand Kit。
5. logo 校验不通过的成片不会交付到用户手里。

### 不做

- 不做 logo 设计生成（已有 `logo-generator`，属于另一个需求）。
- 不追求「AI 直接把文字写对」—— 这是模型能力问题，我们的策略是不让它重画。

## 3. 复用清单（不自研）

| 需求 | 复用对象 |
|---|---|
| 抠图 / 分割 | 商用 API（remove.bg / Clipdrop）或开源模型（SAM / BiRefNet），按成本选；绝不自研分割模型 |
| 带 mask 的图像编辑 | 现有 `openai.images.edit`（已在用，只差 mask 参数） |
| logo 保真校验 | 成熟 CV 库：SSIM / ORB 特征匹配 / OCR / ΔE 色差，不自研度量 |
| 视频 logo 贴合 | 开源 CV 单应矩阵解算 + ffmpeg 透视滤镜，不引入专有软件 |
| 商品页结构化抓取 | JSON-LD / OpenGraph 标准 + 成熟抓取库；Shopify 官方 API |
| 卖点与脚本结构 | 同行已验证的 hook / body / CTA 三段式 |
| 产品图批处理 | 现有 `product-image-service` + 成熟抠图/场景生成方案 |
| 多平台规格 | 各平台官方素材规范表 |
| 工作流编排 | 现有故事板 / 批量队列，不引入新编排框架 |

## 4. 里程碑

| 阶段 | 内容 | 退出条件 |
|---|---|---|
| M1 | C1 度量与自动选路、C2 计费规则 | 能回答成本/耗时；失败零计费有测试 |
| M2 | E1 链接起片（Shopify + 通用 OG）、E2 统一素材库、**B1 产品锚定（抠图 → 锚点 → 路径 A/B → 校验 Gate）** | 贴链接 8 分钟内出片；素材按 SKU 归档；同一 SKU 跨 10 次生成校验通过率 100% |
| M3 | E3 多平台导出、E4 目录级批量、**B2 植入分档 + B3 Brand Kit** | 一键拿到可投素材包；50 SKU 批次跑通；默认植入不再是角标水印 |
| M4 | C3 + B4 品类锁通用化、B5 logo 校验 | 一次通过率 ≥ 60%；糊掉的 logo 不会交付 |

赛马下线在 M1 一并完成（只改导航与文档，不动数据）。

## 5. 风险

1. **抓取合规与稳定性**：目标站点结构变化、反爬。缓解：标准化字段优先（JSON-LD/OG），
   失败必有手工路径，绝不把用户堵死。
2. **供应商单点**：Shuyu 已两次打穿生产。缓解即 C1 的自动降级，且必须先于 E1 上线。
3. **范围膨胀**：E1 很容易长成「什么站都要支持」。缓解：本轮只保证 Shopify + 通用 OG 两条路径达标。
4. **砍赛马的沉没成本情绪**：代码保留、数据保留，只停投入，不做删除决策。
5. **参考图锚定依赖用户上传质量**：没有干净的产品图就锚不住。缓解：产品图工作台先把
   原图修成可用的锚点（这正是它该存在的理由），并在链接起片时优先取商品主图。
