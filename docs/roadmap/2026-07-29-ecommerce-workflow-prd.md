# PRD · Aivora：小商家的内容获客与增长操作系统

- 版本：**v3.1**（2026-07-29，扫完青砚代码后重划分工；OpenCut 确认为观察项）
- 状态：待评审
- 上游：[同行调研](2026-07-29-competitive-review.md)、[0724 整合路线图](2026-07-24-integration-plan.md)

## 基调（CEO 定调）

> **Aivora 是帮助小商家围绕内容获客和增长的 AI 营销操作系统。**

参照模式：**Predis.ai**。实现原则不变：**尽量复现市面已验证成功的方案，不自己发明。**

**构建策略（CEO 定）**：
> 对方做得好的，我们直接拿来用就行；等有量了我们再自己搭。

这条写进本 PRD 的工程原则：**能外接成熟方案的一律先外接**，只在（a）成为差异化护城河
或（b）规模上来后成本/可控性划不来时，才转自建。每条外接依赖都要留好「将来能换掉」的接缝。

> ⚠️ **本版推翻了 v1.0 的两条「不做」。** v1.0 把范围收在「电商素材流水线」，明确写了
> 不做账号发布、不做任何数据分析。按新基调，「操作系统」必须闭环到发布，
> 而竞品**内容**分析是内容工作流的一部分。这两条的翻转在第 2 节单独列出，请重点确认。

## 1. 我们在 Predis 模式里的位置

### 1.1 Predis 是什么模式

一句话进 → 多形态内容出（单图 / 轮播 / 视频 / 文案 / 话题标签）→ 拖拽日历排期 →
一键发布到 IG / FB / LinkedIn / TikTok / Pinterest / Google 商家 → 竞品内容分析给灵感。
集成 Shopify / WooCommerce。目标客户是小商家（96% 评审者来自小企业），$19–41/月为主力档。

它的自我定位很坦白：**不是任何单项最强，但是唯一把生成、设计、视频、排期、竞品分析
打包进一个地方的**——「什么都够用，且都在一处」。

### 1.2 关键洞察：它最弱的一环正是我们最强的一环

| 环节 | Predis | Aivora 现状 |
|---|---|---|
| 内容日历 / 排期 | **最被称赞**（97% 评审者认为重要） | 外接 Postiz 即可追平，不自建 |
| 多平台一键发布 | 有，10–60 个渠道 | 外接 Postiz 即可追平，不自建 |
| **创意层面的胜负归因（赛马）** | 只有竞品内容分析，没有「我的哪个结构在赢」 | **这是我们独有的**：配方↔发布↔表现的链路只有我们完整持有 |
| 图文帖 / 轮播 / 文案 / 话题标签 | 有 | **零**（我们只有视频 + 产品图） |
| 竞品内容灵感 | 有 | **零** |
| **视频质量** | **最弱**：2026 多方评审 6/10，明确说产品实拍、UGC、复杂剪辑不行 | **专业级**：故事板锁、产品一致性、品牌封装、真机验收 |

### 1.3 因此本轮的定位

**骨架能外接的就外接，把力气全部押在两个别人做不到的地方：产品内容质量、创意胜负归因。**

一句话对外表述：**像 Predis 一样顺手，但产品视频是专业级的，而且它会告诉你哪种内容在替你赚钱。**

这不是「再做一个 Predis」——同质化竞争我们赢不了，它已经把「什么都够用」这个位置占了。
我们的位置是「操作系统一样好用，产品内容这一环别人做不到」。

### 1.4 北极星指标（随定位调整）

v1.0 的指标全部围绕「单条成片」，那是素材工厂的指标。操作系统的指标是**持续产出与发布**。

| 维度 | 指标 | 现状 | 目标 |
|---|---|---|---|
| **持续性** | 周活商家中「一周至少发布 3 条内容」的比例 | 无发布能力，无法度量 | 建立度量，≥ 50% |
| **省力** | 从「一句话 / 一个链接」到「一周内容排完期」的耗时 | 无此路径 | ≤ 20 分钟 |
| 质量 | 首次生成即被接受的比例（一次通过率） | 未度量 | 建立度量，≥ 60% |
| 成本 | 单条内容的全链路成本 | 视频已有度量（仅 Shuyu 线路） | 全形态可度量，降低 ≥ 30% |

小商家的真痛点是**发不出去、发得不连续**（Predis 的用户评价里反复出现 inconsistent posting），
不是「单条片子再便宜 10%」。指标必须对着这个痛点。

## 3. 主线一：操作系统骨架（P0）

骨架里**能外接的已经外接**（排期发布走 Postiz），真正要我们自己做的只剩内容形态与广告情报两块。

### O1 · 一句话进，多形态出

Predis 的入口是**一句话**，不是商品链接。小商家常常没有独立站，但一定说得出
「我家做定制百叶窗，想让人来约免费上门量尺」。

| 输入 | 支持度 |
|---|---|
| 一句话 / 一段业务描述 | **P0**，主入口 |
| 一张产品图 | P0 |
| 商品链接（Shopify / 通用 OG） | P0，有独立站的走这条 |

输出形态（当前只有后两项）：

| 形态 | 现状 | 优先级 |
|---|---|---|
| 文案 + 话题标签 | 零 | **P0** |
| 单图帖 | 零（产品图不等于社媒帖） | **P0** |
| 轮播（carousel，多图多屏） | 零 | **P0** |
| 短视频 | 有，且是专业级 | 已有 |
| 产品图 | 有 | 已有 |

**验收标准**：输入一句话，20 分钟内拿到一周可发的内容（含文案与话题标签），无需手工补齐。

### O2 · 排期与多平台发布 —— 青砚已实现，我们只做交接

**这一节是本版最大的减法。** 上一版打算自建日历 + 发布；现在确认**青砚已经做完了**
（Postiz 客户端、PublishJob 状态机、幂等重试、矩阵账号、人工审核、渠道抽象），
Phase C 代码就绪、staging 全绿，仅生产迁移与真机发布未跑。

**我方唯一的工作**：按青砚已写好的占位契约，暴露一个机器鉴权的成片列表接口，
让它的 `aivora-sync` 定时任务能拉走。契约细节与建议追加的配方字段见 §9。

我们**不碰** Postiz、不建日历、不做平台 OAuth、不做发布重试 —— 全部由青砚承担。

### O4 · 同行广告情报与仿写（P0，to B 客户最看重的一环）

**背景（CEO 定调）**：最终客户是 to B，to B 只看效果。同行**已经投放过的**广告是有数据支撑的，
所以最有价值的输入是「扒到同行的 Ads，然后仿写」。

这个判断是对的，而且行业里已经有验证过的做法（Creatify 的竞品广告追踪覆盖千万级 Meta 广告）。
但「扒 Ads + 仿写」里混着三件法律风险完全不同的事，必须拆开：

| # | 做法 | 判断 | 说明 |
|---|---|---|---|
| 1 | **采集同行公开投放的广告**（素材、文案、投放时长、平台） | ✅ **做** | 各大平台的广告透明库是**官方公开接口**，本来就是为透明度设计的 |
| 2 | **提取结构并仿写**（钩子类型、节奏、角度、CTA 模式 → 生成原创内容） | ✅ **做** | 结构、策略、创意方向不受版权保护；受保护的是具体表达。这也是同行的标准做法 |
| 3 | **搬运他人成片换音轨后重发** | ❌ **不做** | 这不是限流问题，是直接的版权侵权。理由见下 |

#### 为什么第 3 条不能做（这不是「后续有问题再换」能覆盖的）

- **风险不落在我们身上，落在客户身上。** 被投诉、被下架、被封号的是发布者，也就是我们的
  to B 客户。他们的账号、他们的品牌、他们收 DMCA。一次下架 + 封号的代价远超一条广告的收益。
- **换平台不解决。** 限流可以换平台，但别人的视频换到哪个平台还是别人的。
- **做成产品会把责任链拉到我们这里。** 一次性手工操作和「平台提供的功能」是两回事。
- 所以这条不是「先交付、有问题再换」的性质。它换不掉。

#### 好消息：合法路径反而更贴 CEO 的原意

CEO 真正要的是「**有数据支撑**」。搬运只拿到素材，拿不到「为什么有效」。
而官方广告透明库会给出一个搬运给不了的信号：**这条广告已经连续投了多久**——
长期在投 = 还在赚钱。这是比「看起来不错」强得多的筛选依据。

所以合法路径拿到的东西更多：素材 + 投放时长 + 平台 + 版本迭代痕迹。

#### 技术方案

```
① 采集
   官方广告透明库（Meta / TikTok / Google 各自的公开广告库）
   + 现有 Apify 抓取（公开自然内容 + 互动数据，discovery-service 已在用）
        ↓
② 结构标注（不存素材本身，存它的骨架）
   钩子类型 / 前 3 秒做了什么 / 镜头节奏 / 卖点顺序 / 社会证明方式 /
   CTA 形态 / 时长 / 画幅 / 已投天数
        ↓
③ 广告配方库（可复用、可 diff、可按行业筛）
        ↓
④ 喂进生成：结构来自配方，画面与文案全部原创
```

关键设计：**第 ② 步之后我们保留的是结构标注，不是别人的素材**。
这既是合规边界，也是工程上更好的选择——结构可以跨行业复用，素材不能。

**验收标准**

1. 输入一个行业/竞品，能拿到该行业**长期在投**广告的结构清单（而不只是一堆视频链接）。
2. 每条配方能说出「它为什么被判为有效」（已投天数、迭代次数等公开信号）。
3. 由配方生成的内容是原创的：画面、文案、口播全部我方生成，可通过重复度检查。
4. 系统内不保存、不再分发他人的成片文件。

#### 明确不做

- 不搬运、不换音轨重发、不做「下载他人成片」的功能入口
  （现有 Apify 返回的 `downloadUrl` 不接入任何产品路径）。
- 不做投放效果看板 / 转化归因 / ROI 报表——平台自带且全量数据在平台手里。
  广告**情报**（别人在投什么）和投放**效果分析**（我投得怎么样）是两件事，只做前者。

## 4. 主线二：赛马闭环（重心）

### 4.0 先纠正我上一版的错误建议

v1.0 我建议停掉赛马，理由是：**平台自带曝光/完播/转化看板，商家每天都在看，
我们做一套更弱的分析没有优势。**

**这个理由在「内容从我们这里发出去」之后就不成立了。** 差别在数据粒度：

| | 平台看板 | 我们 |
|---|---|---|
| 粒度 | **帖子**：这条 1 万播放、300 互动 | **创意结构**：这条用的是哪个钩子、哪个模板、哪个卖点顺序、哪个植入档位 |
| 能回答 | 「这条表现如何」 | 「你最近 40 条里，『前 3 秒直接给结果』比『提问式开场』平均高 3 倍」 |
| 为什么它做不到 | 素材不是平台生成的，它没有「配方」这一维 | 内容是我们生成的、从我们这里发的，配方↔帖子的对应关系只有我们有 |

所以赛马不是「跟平台抢数据分析」，而是**利用只有我们才有的「创意配方 ↔ 发布 ↔ 表现」链路
做创意层面的归因**。CEO 那句「还是得要靠数据吃饭」指的正是这个。

同行也验证过这条路：Arcads 的做法是**一条广告开始赢，就自动派生变体**，
沿着不同钩子、人设、角度扩量。我们要复现的就是这个循环。

### 4.1 闭环长什么样

```
       ┌──────────────── 外部信号 ────────────────┐
       │  O4 同行广告情报：什么结构在长期投        │
       └───────────────────┬──────────────────────┘
                           ↓
                  ┌─────────────────┐
                  │   创意配方库     │ ← 两个信号源共用同一套数据结构
                  └────────┬────────┘
                           ↓
                 生成（我方专业级内容）
                           ↓
         青砚 → Postiz 发布 + 回执（配方随成片带过去）
                           ↓
              表现数据回流（客户自己账号，官方 API）
                           ↓
              赛马：按配方维度判胜负 ──┐
                           ↓            │
                  自动派生赢家变体 ──────┘
```

**关键架构统一**：O4 的外部情报和赛马的内部战绩，**输出到同一套「创意配方」结构**。
外部情报负责冷启动（还没有自己的数据时，用同行长期在投的结构起步），
赛马负责持续优化（有了自己的数据后，按自己的胜负迭代）。

### 4.2 数据从哪来（合规边界很清楚）

赛马读的是**客户自己账号的表现数据**，通过客户授权的官方 API 读取：
Instagram Graph insights、TikTok 官方接口、YouTube Analytics 等。

这与 O4 的「采集同行公开广告」是两件事，也与「爬取他人后台数据」完全无关——
读的是客户自己的、授权过的、自己账号的数据。

### 4.3 交付项

| # | 交付 | 说明 |
|---|---|---|
| R1 | **配方溯源**：每条发出去的内容都能追到它的创意配方 | 赛马的地基。落地方式已明确：随 `/videos` 契约把配方字段带给青砚（§9.4），由它落进 `VideoAsset.metadataJson` |
| R2 | **表现回流**：定时拉取客户账号里我方内容的表现数据 | 只拉我方发出去的帖子，不做全账号分析 |
| R3 | **配方维度胜负判定**：按钩子类型 / 模板 / 时长 / 画幅 / 植入档位分组比较 | 要有最小样本门槛，样本不足时明确说「还判不了」而不是给个假结论 |
| R4 | **赢家自动派生变体** | 复现 Arcads 的循环：判定为赢的配方，自动生成同结构的新变体 |
| R5 | **给商家看的一页结论** | 不做大而全的看板。就回答三件事：哪个结构在赢、下一步建议试什么、我帮你排了什么 |

### 4.4 明确不做

- 不做全账号数据看板、不做跨渠道 ROI 归因报表——那是平台的活，我们只解释**我方内容**的胜负。
- 不做投放（付费广告）层面的优化建议——我们做的是内容获客，不是投放代运营。
- 样本不足时不给结论。宁可说「还判不了」也不给一个会误导商家的排名。

### 4.5 已有实现需要对接

CEO 提到**青砚的仓库里已经打好了赛马和前端发放渠道**。

我目前看不到那个仓库，所以这一节写的是「应该长什么样」，不是「从零怎么写」。
落地前需要：该仓库的访问权限，或一份接口/数据模型说明。
**若已有实现覆盖了 R1–R5 的一部分，本节相应条目改为对接而不是重写。**

## 5. 主线三：产品内容的专业级质量（我们的护城河）

Predis 的视频是 6/10，做不了产品实拍与 UGC。这一环是我们唯一别人抄不走的地方，
必须继续加固而不是稀释。

### 4.1 LOGO 的定型与植入

「产品 LOGO 怎么定型、怎么加进去」是**两件事**，现在两件都只做了最低档：

| | 问题 | 现状做法 | 为什么僵硬 |
|---|---|---|---|
| **定型** | 产品自身的 logo 在生成时走形、乱码、颜色漂移 | 提示词约束 + 单客户硬编码锁 | 提示词管不住像素；换客户就要重写一套 |
| **植入** | 品牌 logo 要出现在成片里 | ffmpeg 把 PNG 钉在画面角落 + 片尾品牌卡 | 不在任何物体上、不随镜头运动、不受画面光照 |

#### 前提：产品带不带 logo，决定做法完全不同

| 品类 | logo 在哪 | 怎么保住它 |
|---|---|---|
| 瓶装 / 包装 / 服饰 | 印在产品自己身上 | 锚住产品像素，只生成周围环境——logo 是「带过去」的 |
| **百叶窗 / 家装 / 上门服务** | **产品上根本没有** | 把 logo 放到现场本来就会有的物件上，用真实资产贴合 |

#### 市场共识：product-first，不是 prompt-first

同行把产品植入分三档，差别只在**产品像素有没有被重画**：纯提示词生成整图（模型重新
诠释产品，**logo 不可辨认**，我们目前就在这一档）→ 模板预设合成（快但同质化）→
**参考图锚定**（锁住产品像素，只生成环境，真实 logo 是「带过去」的，做电商目录的都在这档）。

品牌标识植入同理：静态角标是最低档（投放语境里损害可信度）；进阶是把 logo 作为参考图
投进场景，或用**平面跟踪**贴到画面中的真实平面上并随镜头运动。

#### 复现方案：三层管线

```
用户产品图
  ├─ 第 0 层 · 锚点  抠图 → RGBA + mask + logo 区域框     ← 现在完全没有
  ├─ 第 1 层 · 生成  只画 mask 之外的环境                  ← 现在是整图重绘
  └─ 第 2 层 · 校验  比对 logo 区域，不合格自动重出        ← 现在完全没有
```

**第 0 层 · 产品锚点**（一个 SKU 做一次，之后所有内容复用）

| 产出 | 用途 | 怎么来 |
|---|---|---|
| 产品 RGBA 切片 | 合成时贴回去的真实像素 | 抠图 |
| 产品 mask | 告诉模型「这块不许画」 | 抠图的 alpha 通道 |
| logo 区域框 | 校验层要知道去哪儿看 | 用户框一次（一次性人工换 100% 可靠基准） |

必须先补的地基：`src/lib/providers/remove-bg.ts` 是个**空壳**（有 key 也只是
`// V2: 真实抠图 API 调用` 的 TODO）。整条锚定路线卡在这里，
所以**实施第一件事是抠图，不是模型调优**。抠图是成熟商品，商用 API 或开源分割模型二选一。

**第 1 层 · 只生成环境，不重画产品**

| 路径 | 做法 | 适用 |
|---|---|---|
| **A（首选）** | 把 mask 传给图像编辑接口，产品像素**零重画** | 线路支持 mask 时 |
| **B** | 模型生成环境 → 锚点 RGBA 贴回原位 → 匹配光影 | Shuyu image2 无 mask 能力，走这条 |
| **C（保底）** | 现有提示词约束，仍重绘整图 | 兜底，不再是默认 |

路径 A **只差一个参数**：`openai-image.ts` 的 `composeReferenceImage` 已经在用
`images.edit` 多图参考，但没传 mask，注释老实写着「保持主体一致的前提下**重绘整图**」。
重绘整图 = 让模型逐字符重画 logo = 糊。

**第 2 层 · logo 保真校验（Gate）**

| 判据 | 抓什么问题 | 手段 |
|---|---|---|
| 结构相似度 | 字符走形、笔画断裂 | SSIM / ORB 特征匹配 |
| 文字可读性 | 乱码、多字少字 | OCR 与品牌名字符串距离 |
| 色彩偏移 | 品牌色漂移 | 主色 ΔE 与 Brand Kit 色板比 |

任一不过 → 自动重出，不合格不进交付。**这个通过率就是一次通过率指标**，不必另造尺子。

**视频侧**：i2v 首帧用已过校验的产品图；成片抽帧复检，漂移只重出该镜头；
平面跟踪贴合落在 `brand-overlay-renderer.ts` 新增模式，现有角标保留为保底档。

### 4.2 交付项

- **B1 产品身份锚定** —— 上述三层管线。验收：同一 SKU 跨 10 次生成校验通过率 100%。
- **B2 植入分三档**：自然植入（**默认**）/ 平面跟踪贴合 / 角标尾卡（保底）。
  关键改动一句话：**现状那档从「唯一做法」降为「保底档」，默认不再是它。**
- **B3 Brand Kit** —— 现在只有 logo PNG + 尾卡。补色板、字体、logo 安全区，以及两份可复用配方：
  **Composition**（构图/机位/产品位置）与 **Photography Style**（光线/相机质感/氛围）。
  这两份比色板字体更决定「看起来是不是同一个品牌」，且**要能套用到图文帖与轮播**，不只是视频。
- **B4 客户锁通用化** —— 从单客户硬编码改成按品类配置，新客户选品类而不是等我们写代码。
- **B5 交付前校验** —— 即第 2 层 Gate。

### 4.3 统一素材库（原 E2，保留）

产品图只在工作台底部有「最近产品图」，成品库只装视频。要合成一个库，
收纳上传原图、生成产品图、分镜、成片、**图文帖与轮播**、字幕/导出件，按业务对象组织。

### 4.4 多平台规格导出（原 E3，保留但降级）

有了 O3 一键发布之后，手工导出的重要性下降，但仍需保留给「想自己发」的商家。

### 4.5 不做

- 不做 logo 设计生成（已有 `logo-generator`）。
- 不追求「让 AI 直接把文字写对」——那是模型能力问题，策略是不让它重画。

## 6. 主线四：成本 / 速度 / 质量工程

不产出新页面，但它是能不能规模化服务小商家的底座。

### C1 · 线路可观测与自动降级（P0）

**已落地**：线路健康画像（成功率、P50/P95、单条成本）、成本快照落库、主线路不可用时
自动降级。第一次度量就量出 buddy(Shuyu) 7 天成功率 **28.6%**。

**仍缺**：**能力探测**而非存活探测——定期校验套餐 ID、分辨率、音频能力，漂移即告警并降级
（0728 套餐轮换、0729 线路崩溃都栽在这个盲区）；用户侧一句话提示当前线路与预计消耗。

### C2 · 定价不惩罚迭代（P0，需财务确认）

调研结论：**流失头号原因不是质量差，而是积分模型惩罚正常使用**（有用户 15 分钟烧完额度当天退订）。

1. 失败、被安全拦截、供应商退款 → **一律不计费**，界面上明说。
2. 迭代（改帧、换构图、换文案）**显著低于**最终出片价格。
3. 「取消这一轮」永远免费。
4. 价格页要能回答「我一个月大概花多少钱」。

注：Predis 也是 credits 制且被诟病同一问题。这里**不复现同行的坑**，反而是差异点。

### C3 · 一次通过率（P1）

品类锁通用化（= B4）；「首次即被接受」比例作为质量北极星；评分标准取自主线四的 eval rubric。

## 7. 主线五：接入 Seedance 导演体系，锁死镜头与模板（P1）

[Emily2040/seedance-2.0](https://github.com/Emily2040/seedance-2.0)（MIT，v6.6.0）值得接，
**但接在设计时，不是运行时**。它绑定的正是 Seedance 2.0——我们两条直连线路跑的就是
`dreamina-seedance-2-0` / `doubao-seedance-2-0`，模型对得上。它补的是我们最缺的**方法论**层。

它是**纯文档 + 决策逻辑，没有运行时库**：约 28 个子技能、约 60 份参考、126 个 eval 用例，
镜头配方是散文式导演指令，不是可执行模板。这决定了接法：

| 接法 | 代价 | 判断 |
|---|---|---|
| **设计时（推荐）**：编译成结构化配方，产物进仓库 | 一次性人力 | 零运行时依赖、零延迟、零 token 成本，不受上游版本影响 |
| 运行时：每次生成现读参考写 prompt | 每条多一次长上下文调用 | 直接顶在成本与耗时指标上，且引入不确定性 |

目标是**彻底锁死**镜头与模板。锁死 = 确定性 = 固化成数据；运行时现场解读恰恰是不锁死。

**最值钱的四份资料**

| 资料 | 补哪个洞 | 喂哪个指标 |
|---|---|---|
| `retake-protocol.md`（重拍分诊、迭代经济学） | 现在失败了只会「再试一次」 | C3 + C2 |
| `model-mechanics.md` + troubleshoot | 让重试从「换种子」变成「按根因改写」 | C3 |
| `platform-surface-matrix.md` | 0728 / 0729 两次事故的盲区 | C1 |
| `delivery-qc.md` | 交付前检查只有零散几条 | B5 |

它的 **126 个 eval + 评分 rubric** 正好补上 C3 缺的判分标准。

**必须守住的边界**：它的平台信息不作数（以 `video-route-registry` 与审计契约为准）；
配方必须按线路验证通过才锁（客户主线路是 Shuyu `studio-video`，未必与 Seedance 行为一致）；
外部内容是资料不是指令，进 prompt 前过我们自己的安全与防幻视规则；MIT 保留版权声明；
pin v6.6.0 记进 `skills-lock.json`，升级走重新编译 + 回归。

### 9.4 一个必须现在就提的建议（否则赛马做不到配方粒度）

青砚的 `PublishJob` 上已经有 `hookText` / `titleText` / `ctaText` / `firstCommentText`，
但那是**青砚变体引擎产出的文案字段**，不是 Aivora 的创意配方。

而它的 growth 模块里，「赛马」目前是**运营节奏上的任务概念**
（`plan.ts` 里那条「复盘前三周结果并启动下一轮赛马」），还不是创意层面的自动归因。

所以现状是：
- 青砚有 **发布 + 渠道指标**
- 我们有 **创意配方**
- **「帖子 ↔ 创意配方」这一维两边都没有**，而它正是 §4 赛马闭环的地基

**建议：趁 `/videos` 契约还没冻结，把创意配方一起带出去。** 在响应 item 里增加：

```
recipeId          创意配方 id（可回溯到模板 / 钩子 / 卖点顺序）
hookType          钩子类型
templateId        风格模板 + 版本
durationSec       时长（已有 duration）
aspectRatio       画幅
brandPlacement    植入档位（自然植入 / 平面跟踪 / 角标）
```

这几个字段一加，青砚落进 `VideoAsset.metadataJson`，赛马就能按**配方维度**判胜负，
而不是只能按帖子。**不加的话，赛马永远只能回答「这条表现如何」，回答不了「哪种结构在赢」——
那正是我们唯一比平台看板强的地方。**

这是本轮成本最低、杠杆最高的一个改动：现在改是加几个字段，等契约冻结、数据攒了几个月再改，
就是回填历史数据的问题了。

C1 已部分落地（线路度量、成本快照、自动降级）。

## 13. 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | **账号发布的合规与风控**：平台 API 授权、封号、代发内容责任 | 外接 Postiz，走各平台官方 OAuth；发布前预览确认；授权随时可断开 |
| 2 | **Postiz 是 AGPL-3.0** | 传染风险由青砚侧承担（它才是集成方）；我方不引入 Postiz 代码，只与青砚的接口对话 |
| 3 | **契约一旦冻结，配方字段就难加了** | §9.4 的字段现在加是几行代码，等数据攒几个月后再加就变成历史回填问题。这是本轮最紧的时间窗 |
| 4 | **青砚的发布链尚未真机验证**：Phase C 生产迁移未执行、真实社媒发布未跑过 | 我方接口先上，配合它做一次端到端真机；在真机通过前不对外承诺发布能力 |
| 5 | **供应商单点**：Shuyu 已两次打穿生产，7 天成功率 28.6% | C1 自动降级必须先于任何对外承诺上线 |
| 6 | **范围膨胀**：功能面仍然很宽，本质是复现一整个操作系统 | 里程碑按「骨架先立、护城河并行」切；每个 M 有独立可交付价值，不做大爆炸发布 |
| 7 | **广告情报的合规边界滑坡**：从「提取结构」滑到「复用素材」 | 采集层只保留结构标注不落素材文件；下载入口在代码层不存在，靠回归测试守住 |
| 8 | **与 Predis 同质化**：只复现骨架会变成更差的 Predis | 差异化必须落在主线二：它视频 6/10，我们是专业级。骨架追平即可，不追平它的每个细节功能 |
| 9 | **外部方法论与我方线路不匹配** | 配方先按线路验证再锁；宁可少锁几个也不锁错 |
| 10 | **参考图锚定依赖上传质量** | 产品图工作台先把原图修成可用锚点；链接起片优先取商品主图 |
