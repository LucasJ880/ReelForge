## 每次上线的固定步骤

1. `npm run typecheck` + `npm run lint` + 全量测试（Node 22+：`PATH=/opt/homebrew/bin:$PATH node --import tsx --test tests/*.test.ts`）全绿。
2. 前端改动在本地预览里实际点一遍（`preview_start name=app`，真机模式、CEO 测试账号已登录）。
3. 带迁移：先在分支上 `npm run db:migrate:deploy`，再合并。
4. 开 PR 直接对 `main`（不叠 PR）→ 等 CI → `gh pr merge <n> --merge`。
5. 合并后看 `/api/health` 的 `release` 是否等于新提交，再看 prod-smoke 工作流。红了先读日志。

## 交付清单（给用户验收）

验收时建议按这个顺序点一遍（都在线上）：

1. **创作页**（空白状态）：描述框下面有「接着拍这些商品」四格 → 点一格，商品图和描述带回来。
2. 写一句 8 个字以上的描述 → 出现「换个开头」「商品尺寸」→ 填尺寸，描述末尾多一行「商品实际大小：…」。
3. 「更多设置」→ 口播稿下面是「N 字 · 说完约 X 秒」，写超了会变红。→「字幕与 BGM 高级设置」里曲目有 9 项，选一首能试听；收起后摘要里写着选了哪首。
4. 点「生成 AI 故事板」→ 提示卡下面有三段进度。故事板出来后，「更多设置」里的口播稿 / 字幕 / 配乐 / 落款 / 线路仍然能改。
5. **成片详情**：下载按钮下面有四个「换个开头再做一条」；点「不满意」选原因提交后，出现对应的下一步按钮；
   「换字幕 / BGM / 片尾落款」里选一首配乐重拼（不扣额度）。
6. **品牌页**：编辑品牌包，右边是片尾落款预览。

没有在界面上实际点过、只有测试覆盖的：第 4 步（要真出一次故事板，付费）、第 5 步的「下一步」按钮（要写一条真实评价）、
多条同时生成时的排队说明（要真的同时出两条）。
