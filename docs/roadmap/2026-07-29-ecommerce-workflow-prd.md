# PRD · 电商工作流复现与成本 / 速度 / 质量三件套

- 版本：**v1.0 定稿**（2026-07-29）
- 状态：待评审
- 上游：[同行调研](2026-07-29-competitive-review.md)、[0724 整合路线图](2026-07-24-integration-plan.md)

**一句话**：不做投放分析、不做赛马，把电商商家从「有商品」到「有一整套可投素材」这条流水线，
做得比谁都快、比谁都便宜、比谁都稳；竞争力用三个可测的数字定义，不用功能条数定义。

## 1. 需要拍板的四个决策

这四条决定了后面所有排期，其余内容都是它们的展开。

| # | 决策 | 建议 | 影响面 |
|---|---|---|---|
| 1 | 是否停掉赛马与投放数据分析 | **停投入，但不删代码不迁数据**，只从主导航摘掉 | 释放一条主线的人力；放弃一个已投入的方向 |
| 2 | 品牌植入的默认档 | 从「角标水印」换成**「自然植入」**，角标降为保底档 | 直接改变所有客户成片的观感 |
| 3 | 定价是否改成「不惩罚迭代」 | **失败零计费、迭代低价、取消永远免费** | 商业模型改动，需财务确认 |
| 4 | 是否接入外部开源导演体系 | **接，但接在设计时**（编译成配方数据），不接运行时 | 引入 MIT 外部依赖；一次性人力投入 |

## 2. 战略取舍

### 2.1 我们不做什么

**不做投放数据分析，也不做赛马择优。**

TikTok / 小红书 / YouTube 自带曝光、完播、转化的原生看板，商家每天都在看。
我们在别人主场做一套更弱的数据分析，既拿不到全量数据，也说服不了用户改变习惯。

处置方式（保守，不做删除决策）：

- 从主导航移除 `/app/racing` 入口，降级为内部只读归档。
- `racing-service` / `scoring-service` / `sweep-service` / `business-metrics-import` 停止新增投入。
- `publish-service` 中「导出 / 发布素材」的部分保留（属于电商工作流），「效果评估」部分剥离。
- 验收：主导航不再出现赛马；现有数据仍可通过 internal 路径查看。

### 2.2 竞争力的三个数字

| 维度 | 指标 | 现状 | 目标 |
|---|---|---|---|
| 成本 | 单条合格成片的全链路成本 | 已建立度量（本轮已落地） | 降低 ≥ 30% |
| 速度 | 从「贴商品链接」到「第一条可用成片」的 P50 | 无此入口 | ≤ 8 分钟 |
| 质量 | 首次生成即被接受的比例（一次通过率） | 未度量 | 建立度量，≥ 60% |

### 2.3 取舍原则

**能用成熟开源工作流 / 已验证的同行做法解决的，一律直接复用，不自研。**

## 3. 主线一：电商工作流复现

### E1 · 商品链接起片（P0，本轮核心）

**用户故事**：我是电商商家，把商品详情页链接贴进来，几分钟后拿到一组可投的产品图和短视频。

```
商品 URL
  → 抓取（标题 / 卖点 / 价格 / 主图组 / 规格）
  → 结构化商品档案（SKU Profile）
  → 自动填充：产品图工作台 + 创作描述 + 品牌包
  → 故事板 → 成片
```

**范围**

- 本轮只保证两条路径达标：**Shopify + 通用 OG / JSON-LD**。淘宝 / 天猫 / Amazon 为后续。
- 抓取失败必须优雅降级为「手工上传 + 手工描述」，不能把用户堵死在入口。
- 抓到的图先过产品图工作台，成为产品锚点（见主线二）。
- 复用：`selling-point-service`、`product-image-service`、`storyboard-service` 全部现成，
  新增的只有抓取层与 SKU Profile 持久化。

**验收标准**

1. 贴入一个 Shopify 商品链接，无需任何额外输入即可进入故事板环节。
2. 抓取结果对用户完全可见可编辑（标题、卖点、选中的图），不是黑盒。
3. 抓取失败时给出明确原因与手工路径，**不消耗积分**。
4. P50 从贴链接到第一条成片 ≤ 8 分钟。

**不做**：竞品广告库、爬取他人投放素材。

### E2 · 统一素材库与 SKU 素材包（P0）

**问题**：产品图只在工作台底部有「最近产品图」，成品库只装视频，文案却写「已进入素材库」——
用户找不到自己的东西，图和片是两个割裂的世界。（文案已先改成不撒谎，功能仍缺。）

**范围**

- 一个素材库，收纳：上传原图、生成产品图、故事板分镜、成片、字幕 / 导出件。
- 以 **SKU 为组织单位**：一个商品下挂它的全部素材，而不是按时间倒序的一锅粥。
- 每个资产统一支持：预览、下载、继续编辑、送进单条 / 批量视频生产。
- 与 E1 打通：链接起片自动创建 SKU 并归档全部产物。

**验收标准**

1. 任意生成物在生成后 5 秒内出现在素材库对应 SKU 下。
2. 下载对所有资产类型可用（图 / 视频 / 字幕），跨域托管也必须真下载。
3. 「成品库」与「产品图库」合并为一个入口，导航不再有两个近义词。

### E3 · 多平台规格与一键导出（P1）

- 输出预设：TikTok / Reels / Shorts（9:16）、小红书（3:4 + 9:16）、商品主图（1:1）、详情页横版（16:9）。
- 一个 SKU 一键导出「投放素材包」：多规格视频 + 主图 + 字幕 SRT + 文案，打包 zip。
- Shopify 商品图回写为选做，需商家授权。

**验收标准**：一次导出得到可直接上传各平台的文件，无需二次裁剪。

**不做**：代投放、账号托管发布（合规与账号风险不成比例）。

### E4 · 目录级批量（P1）

从「一次一个 SKU」升级到「一次一批 SKU」——上传 CSV / 连接店铺 → 批量起片。
沿用现有批量队列、熔断、退款与恢复机制，只把输入维度从模板换成 SKU 列表。

**验收标准**：50 个 SKU 的批次可提交、可暂停、可逐条取消、失败不重复计费。

## 4. 主线二：产品 LOGO 的定型与植入

### 4.1 问题：一个词底下藏着两件事

| | 问题 | 现状做法 | 为什么僵硬 |
|---|---|---|---|
| **定型** | 产品自身的 logo 在生成时走形、乱码、颜色漂移 | 提示词约束 + 单客户硬编码锁 | 提示词管不住像素；换个客户就要重写一套 |
| **植入** | 品牌 logo 要出现在成片里 | ffmpeg 把 PNG 钉在画面角落 + 片尾品牌卡 | 不在任何物体上、不随镜头运动、不受画面光照 |

`brand-overlay-renderer` 的注释已经写明了理由：AI 供应商对精确文字 / logo / ® / 细线条的
还原不稳，所以「唯一可靠的方案」是自己在合成层叠上去。这个判断今天只对了一半——
它对**画面里的品牌标识**成立，但**产品自带的 logo** 已经有更好的解法。

### 4.2 前提：产品带不带 logo，决定做法完全不同

| 品类 | logo 在哪 | 怎么保住它 |
|---|---|---|
| 瓶装 / 包装 / 服饰 | 印在产品自己身上 | 锚住产品像素，只生成周围环境 —— logo 是「带过去」的 |
| **百叶窗 / 家装 / 上门服务** | **产品上根本没有** | 把 logo 放到现场本来就会有的物件上，用真实资产贴合 |

### 4.3 市场共识：product-first，不是 prompt-first

同行把产品植入分三档，差别只在**产品像素有没有被重画**：

1. **纯提示词生成整图** —— 模型会重新诠释产品：颜色偏移、材质抹平、**logo 不可辨认**。
   这是我们目前生成模式的档次。
2. **模板 / 预设合成** —— 快，但全行业共用同一批场景，模板光线常与产品原光冲突。
3. **参考图锚定** —— 锁住产品像素，只生成周围环境；**真实 logo 是「带过去」的，
   不是被逐字符重画的**。做电商目录的都在这一档。

品牌标识的植入同理分档：静态角标水印是最低档（投放语境里甚至损害可信度，
专业工具都强调无水印导出）；进阶是把 logo 作为参考图投进场景，
或用**平面跟踪**把 logo 贴到画面中的真实平面上并随镜头运动。

### 4.4 复现方案：三层管线

一句话：**产品像素不重画，只生成它周围的东西，然后验一遍。**

```
用户产品图
  │
  ├─ 第 0 层 · 锚点  抠图 → RGBA + mask + logo 区域框     ← 现在完全没有
  │
  ├─ 第 1 层 · 生成  只画 mask 之外的环境                  ← 现在是整图重绘
  │
  └─ 第 2 层 · 校验  比对 logo 区域，不合格自动重出        ← 现在完全没有
```

#### 第 0 层 · 产品锚点

一个 SKU 一次性产出、之后所有图与视频复用：

| 产出 | 用途 | 怎么来 |
|---|---|---|
| 产品 RGBA 切片 | 合成时贴回去的真实像素 | 抠图 |
| 产品 mask | 告诉模型「这块不许画」 | 抠图的 alpha 通道 |
| logo 区域框（bbox） | 校验层要知道去哪儿看 | 用户在锚点上框一次（一次性人工换 100% 可靠基准） |

**必须先补的地基**：`src/lib/providers/remove-bg.ts` 是个**空壳**——没有 key 原样返回，
有 key 也只是 `// V2: 真实抠图 API 调用` 的 TODO。整条锚定路线卡在这里，
所以**实施的第一件事是抠图，不是模型调优**。抠图是成熟商品，商用 API 或开源分割模型二选一。

#### 第 1 层 · 只生成环境，不重画产品

按线路能力选档，优先级从上到下：

| 路径 | 做法 | 适用 |
|---|---|---|
| **A（首选）** | 把 mask 传给图像编辑接口，模型只在产品之外作画，产品像素**零重画** | 线路支持 mask 时 |
| **B** | 模型自由生成环境 → 把锚点 RGBA 贴回原位 → 匹配光影 | Shuyu image2 线路目前没有 mask 能力，走这条 |
| **C（保底）** | 现有的提示词约束，模型仍重绘整图 | 兜底，不再是默认 |

**路径 A 我们只差一个参数**：`openai-image.ts` 的 `composeReferenceImage` 已经在用
`images.edit` 多图参考，但**没有传 mask**，所以注释老实写着「在保持主体一致的前提下**重绘整图**」。
重绘整图 = 让模型逐字符重画 logo = 糊。加 mask 参数 + 第 0 层的 mask 即可改档。

路径选择复用 C1 的能力探测：探测到线路支持 mask，自动升到路径 A。

#### 第 2 层 · logo 保真校验（Gate）

拿第 0 层的 bbox 去结果里取同一块，和品牌 logo 资产比三个判据：

| 判据 | 抓什么问题 | 手段 |
|---|---|---|
| 结构相似度 | 字符走形、笔画断裂 | SSIM / ORB 特征匹配对齐后比对 |
| 文字可读性 | 乱码、多字少字 | OCR 结果与品牌名做字符串距离 |
| 色彩偏移 | 品牌色漂移 | 主色 ΔE 与 Brand Kit 色板比 |

任一不过 → **自动重出**（先原路径重试，连续失败降到路径 B），不合格的成片不进交付。
**这个通过率本身就是 C3 的一次通过率指标**，不必另造尺子。

#### 视频侧

1. **首帧锚定**：i2v 首帧用已过校验的产品图，logo 从首帧带进视频。
2. **抽帧复检**：成片抽样跑第 2 层，漂移超阈值只重出该镜头，不整条重来。
3. **平面跟踪贴合**：逐帧解算目标平面的单应矩阵，把 logo 按透视贴上去。
   落点是 `brand-overlay-renderer.ts` 新增一种模式，现有固定角标原样保留为保底档。

### 4.5 交付项

**B1 · 产品身份锚定** —— 即上面的三层管线。
验收：同一 SKU 跨 10 次生成，第 2 层校验通过率 100%（可自动化测，不靠人眼）。

**B2 · 品牌植入分三档，由用户选**

| 档位 | 做法 | 适用 |
|---|---|---|
| 自然植入 | logo 来自真实物料 / 产品参考图，长在场景里 | **默认**；最像真广告 |
| 平面跟踪贴合 | logo 贴到画面中的平面并随镜头运动 | 需要 logo 更清晰可读时 |
| 角标 / 尾卡 | 现有 ffmpeg 合成层 | 保底，供应商不给力或客户明确要水印时 |

关键改动只有一句：**现状那一档从「唯一做法」降级为「保底档」，且默认不再是它。**

**B3 · 品牌包升级成 Brand Kit** —— 现在是一个 logo PNG + 一张尾卡。要补色板、字体、
logo 安全区与最小尺寸，以及两份**可复用配方**：

- **Composition**：构图、机位角度、产品在画面里的位置
- **Photography Style**：光线、相机质感、氛围、色调

这两份是同行做目录级一致性的核心：一个 SKU 目录定一次，后面所有图和片套同一份，
比色板字体更能决定「看起来是不是同一个品牌」。

**B4 · 客户锁通用化** —— `sunnyshutter-brand-pack` / `client-lock-profiles` 目前是单客户硬编码，
改成按品类配置的锁模板（窗帘、服饰、食品、3C…），新客户选品类而不是等我们写代码。

**B5 · 交付前自动校验 logo** —— 即第 2 层 Gate，不合格自动重出，不流到用户手里。

### 4.6 样例：SunnyShutter

SunnyShutter 属于「产品上没有 logo」那一类。百叶窗本身不印 logo，所以三层管线里的
**产品锚定解决的不是 logo，而是百叶窗本身**不被模型重新诠释（叶片数、叶片宽度、木色、窗框比例）。
logo 是另一条线：品牌物料作为场景道具。

**四个自然植入位**（按贴合稳定性排序）：

| # | 载体 | 为什么成立 |
|---|---|---|
| 1 | 窗台上的样品册 / 色卡 | 销售上门必带；平面正对镜头，贴合精度最高 |
| 2 | 安装工工服胸口 | 出现在量尺 / 安装镜头里，顺带讲了服务属性 |
| 3 | 工具箱 / 包装箱侧面 | 地面前景，镜头推进时自然入画，不抢窗户主体位 |
| 4 | 门口服务车车贴 | 仅用于外景开场，不适合每条都放 |

共同点：logo 出现在一个**真实会出现的载体**上——画面里它是道具，不是水印。

**佐证：绝不能让模型自己画品牌物料。** v2 流水线里有一条专门处理叫「裁尾杀假名片」——
模型会凭空造出带字的名片，而字是假的、乱的。这证明两件事：模型确实会主动生成品牌物料，
且它写的字不能用。所以不是求它写对，而是**不让它写**。

### 4.7 实施顺序（依赖是硬的）

```
抠图能力（补 remove-bg 空壳）
      ↓
产品锚点资产（RGBA + mask + bbox）
      ↓
路径 A / B 生成  ──→  logo 校验 Gate  ──→  首帧锚定进视频
      ↓                                        ↓
   Brand Kit 配方                        平面跟踪贴合
```

### 4.8 不做

- 不做 logo 设计生成（已有 `logo-generator`，属另一个需求）。
- 不追求「让 AI 直接把文字写对」—— 那是模型能力问题，我们的策略是不让它重画。

## 5. 主线三：成本 / 速度 / 质量工程

这条线不产出新页面，但它才是护城河本身。

### C1 · 线路成本与速度可观测，并据此自动选路（P0）

**本轮已落地**：线路健康画像（成功率、P50/P95 耗时、单条成本）、单条成本快照落库、
主线路不可用时自动降级。第一次度量就量出 buddy(Shuyu) 7 天成功率 28.6%。

**仍缺**：**能力探测**而不只是存活探测——定期校验套餐 ID、支持的分辨率与音频能力，
漂移即告警并自动降级。0728 套餐 ID 轮换、0729 线路崩溃都栽在这个盲区。
以及用户侧的一句话提示：当前线路 / 预计耗时 / 预计消耗。

**验收标准**

1. 任一线路连续失败达阈值，新任务自动切换到可用线路，用户无感或仅收到一次提示。
2. 后台可回答：「上周每条成片平均花了多少钱、多少分钟」。
3. 供应商接口漂移能在事故前被探测到。

### C2 · 定价不惩罚迭代（P0，产品 + 工程共同项）

调研结论：**用户流失的头号原因不是质量差，而是积分模型惩罚正常使用**
（有用户 15 分钟烧完额度当天退订）。

1. 失败、被安全拦截、供应商退款的任务，**一律不计费**，且在界面上明说。
2. 迭代阶段（故事板改帧、产品图换构图）**显著低于**最终出片的价格。
3. 「取消这一轮」永远免费。
4. 价格页必须能回答「我一个月大概花多少钱」，而不是只给一个积分数。

**验收标准**：任意失败路径的账单增量为 0 且有回归测试覆盖；用户可在生成前看到预计消耗。

### C3 · 一次通过率（P1）

- 把 v2 已验证的锁（故事板抽卡择优、主体锁、防幻视、裁尾）通用化为可配置的品类锁（= B4）。
- 度量「首次生成即被接受」的比例，作为质量北极星。评分标准取自主线四的 eval rubric。

## 6. 主线四：接入 Seedance 导演体系，锁死镜头与模板

### 6.1 结论

[Emily2040/seedance-2.0](https://github.com/Emily2040/seedance-2.0)（MIT，v6.6.0）值得接，
**但要接在设计时，不是运行时**。

它绑定的正是 Seedance 2.0 —— 我们两条直连线路跑的就是 `dreamina-seedance-2-0` /
`doubao-seedance-2-0`，模型对得上。它补的是我们最缺的一层：**方法论**。

### 6.2 它是什么，这决定了怎么接

它是**纯文档 + 决策逻辑，没有运行时库**：约 28 个子技能、约 60 份参考文档、126 个 eval 用例，
全是结构化 markdown，执行完全依赖 LLM 对这些文件的解读；镜头配方是散文式导演指令，
不是可直接执行的代码模板。

| 接法 | 做什么 | 代价 | 判断 |
|---|---|---|---|
| **设计时（推荐）** | 装进开发环境，用它把模板**编译**成结构化镜头配方，产物固化进仓库 | 一次性人力 | 零运行时依赖、零延迟、零 token 成本，不受上游版本变动影响 |
| 运行时 | 每次生成让 LLM 现场读参考文档写 prompt | 每条片子多一次长上下文调用 | 直接顶在「单条成本」与「P50 耗时」两个北极星上，且引入不确定性 |

目标是**彻底锁死**镜头与模板。锁死 = 确定性 = 固化成数据；运行时现场解读恰恰是不锁死。

### 6.3 怎么接：一个离线的「配方编译」步骤

和已有的 `tokens:generate` / `codemap:build` 同一类：设计时跑、产物进仓库、有回归测试。

```
现有 31 个模板 + 想复现的镜头风格清单
        ↓  用 directing-engine + genre library(33 例) + 分镜头子技能
结构化镜头配方（镜头功能 → 机位 / 光线 / 调度 / 表演 / 声音的一致选择）
        ↓  固化
style template 数据 + segment planner 规则  →  进 git，可 diff、可回归
```

**编译产物是数据不是文档**：模板从「一段提示词骨架」升级成「每个镜头的功能定义 +
一组互相自洽的技术选择」，之后每次生成走同一份配方，不再每条碰运气。

### 6.4 最值钱的四份资料

| 资料 | 补我们哪个洞 | 喂哪个指标 |
|---|---|---|
| `retake-protocol.md`（重拍分诊、迭代经济学、尝试预算） | 现在失败了只会「再试一次」，没有分诊方法论 | C3 + C2 |
| `model-mechanics.md`（生成器 8 个核心机制）+ troubleshoot | 让重试从「换个种子」变成「按根因改写」 | C3 |
| `platform-surface-matrix.md`（模型能力 vs 平台行为差异） | 0728 / 0729 两次事故的盲区 | C1 |
| `delivery-qc.md`（交付前 preflight 清单） | 交付前检查只有零散几条 | B5 |

另有两项与主线二咬合：它的**品牌 / IP 安全改写**规则与我们「不让模型自己画品牌物料」
是同一判断；它的 **126 个 eval + 评分 rubric** 正好补上 C3 缺的判分标准。

### 6.5 必须守住的边界

1. **它的平台信息不作数。** 它自己声明平台信息会过时；线路能力以 `video-route-registry`
   与审计契约为准。
2. **模型耦合要验证。** 它绑 Seedance 2.0，而客户主线路 buddy 走 Shuyu `studio-video`，
   行为未必一致。配方必须**按线路验证通过后才锁**。
3. **外部内容是资料，不是指令。** 其文本进入我们的 prompt 前要过我们自己的安全与防幻视规则；
   与我们的内容审核冲突时以我们的为准。
4. **MIT 合规。** 保留版权声明；编译出的配方注明来源。
5. **版本 pin。** 锁 v6.6.0 记进 `skills-lock.json`，升级走重新编译 + 回归，不静默跟随上游。

### 6.6 验收标准

1. 模板配方是仓库里可 diff 的数据，不是运行时现读的文档。
2. 生成链路**不新增**任何运行时长上下文调用——单条成本与 P50 不因此上升。
3. 每条锁死的配方都有按线路验证的证据；未验证的不上线。
4. 上游升版不会自动改变线上出片行为。

## 9. 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | **供应商单点**：Shuyu 已两次打穿生产，7 天成功率 28.6% | C1 自动降级必须先于 E1 上线 |
| 2 | **抓取合规与稳定性**：站点结构变化、反爬 | 标准化字段优先（JSON-LD / OG），失败必有手工路径 |
| 3 | **范围膨胀**：E1 容易长成「什么站都要支持」 | 本轮只保证 Shopify + 通用 OG 两条达标 |
| 4 | **外部方法论与我方线路不匹配** | 配方一律先按线路验证再锁；宁可少锁几个也不锁错 |
| 5 | **参考图锚定依赖上传质量**：没有干净产品图就锚不住 | 产品图工作台先把原图修成可用锚点；链接起片优先取商品主图 |
| 6 | **砍赛马的沉没成本情绪** | 代码保留、数据保留，只停投入，不做删除决策 |
