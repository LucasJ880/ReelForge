## 审计结论：线上和导演线路差在哪（2026-11-17）

**结构上差得没有想象的大。** 线上 15 秒的片本来就是「一张开场帧 + 一份时间线提示词 + 一次生成」，和导演线路一样；
30 秒才是两段 15 秒各生成一次再拼（`planSegments`，`src/lib/duration/segment-planner.ts`），60 秒是四段。
差的是**提示词由谁写、按什么规矩写**：

| 导演线路的规矩 | 线上现在 | 在哪 |
|---|---|---|
| 快销节奏：钩子 ≤2 秒、15 秒六个镜头 | 固定四个等长镜头（4/4/3/4 秒），提示词里写死「slow and steady」，镜头卡要求「最多一个慢动作」 | `storyboard-beats.ts`（`STORYBOARD_BEATS_SHORT`、`groundSegmentPromptForSeedanceOpeningFrame`）、`shot-cards.ts:186` |
| 先想场景 | 没有。镜头卡只是把商家的描述转写一遍；出方案得到的钩子、卖点根本没进出片提示词 | `creative-strategist.ts` 的产出没人用 |
| 口播：声音描述一次、每句台词放在它被念的镜头里 | 整篇口播稿当一整块塞在最后 | `prompt-intelligence.ts` 的 `composeSeedancePrompt` |
| 配乐：有拍子、写进提示词 | 提示词里明令**不要**背景音乐；配乐是合成时另混的曲库曲子（默认「不添加」），切点不跟拍 | `storyboard-beats.ts:297` |
| 全程要求用正面描述 | 一串否定句（KEY CONSTRAINTS + Negative constraints） | 同上 |
| 镜头卡由导演认真写 | 由快档模型（gpt-5.6-terra）纯文字写，每项 ≤15–20 个词；超时就静默退成「faithful product reveal」 | `shot-cards.ts:274` |
| 30 秒一次生成十二个镜头 | 两次互不相干的生成 | `planSegments` |
| 右上角透明 Logo | 没有（`CORNER_LOGO_WATERMARK_ENABLED=false`，`cornerLogoFilter` 只在 scripts 里） | |
| 字幕按每句台词的时间 | 同一个合成器，但按字数摊满整段 | `stitch-pipeline.ts` |

另外三件事：

- **「自动匹配（推荐）」是一段正则**，不是模型（`recommendStyleTemplate`，`style-templates.ts:625`）。
- **选哪个模板几乎不影响单条视频**：34 个模板只在批量里原样用；单条流程里模板只留下几行锁定语。
  所以只往目录里加一个「电商快销」条目，单条出片不会有任何变化——必须连着出片逻辑一起改。
- 客户确认的四帧故事板，**只有第一帧真的交给了出片模型**，后三帧没用上。

**定下的做法（审计的建议，我同意）：** 不改线上的外壳，换掉写提示词的那一层——

1. 把 `scripts/lib/director-plan.ts` 挪进 `src/lib/video-generation/`（它是纯逻辑），scripts 那边改成转出。
2. 新写一个「导演写手」`director-writer.ts`：一次看图的模型调用（创意档 gpt-5.6-sol，可用环境变量换 gpt-6-astra 对比），
   系统提示词从 skill 提炼，输出就是一份 `DirectorJob`；用 `lintDirectorJob` 校验，把错误和节奏提醒喂回去最多修两次；修不好就退回现在的老路并记一条降级。
3. 故事板：这条路只出一张开场帧（`buildFramePrompt`），面板显示这一帧 + 可读的镜头与台词清单。脚本存在现有的 JSON 字段里，**尽量不加列**。
4. 出片：有脚本时提示词直接用 `buildVideoPrompt(job)`；字幕时间用 `directorSpokenLines` / `scriptSpeechWords`；配乐由模型原生出，曲库默认不混。
5. 先以「电商快销」模板的形式上（15 秒、快销片种），带一个总开关，写手失败就走老路；真机对比过再设成默认、扩到 30 秒，然后删掉老的那几层。

对齐之后可以删的（先查引用再删）：`creative-strategist.ts`、`consistency-bible.ts`、`planning-mode.ts`、`prompt-intelligence.ts` 的大部分、
`shot-cards.ts`、`story-english.ts`、`storyboard-beats.ts` 里的 `ground*` 函数、`style-templates.ts` 里的老脚手架与正则匹配、
`visual-reference-analysis.ts`、出方案预览那条链、故事板第 2–N 帧的重抽与分段重做界面。

没定的：Shuyu 通过我们的适配器收不收 30 秒一次生成（适配器常量允许 30；导演线路的 30 秒片因为 Shuyu 故障还没真跑成）；
gpt-5.6-sol 当写手的水平（要花钱对比）。

## 每一批怎么验（这次踩过的坑）

```bash
export PATH=/opt/homebrew/bin:$PATH        # 要 Node 22+
```
