# Aivora 导演线路

2026-11-16 定的线路：**Claude 写脚本与提示词 → OpenAI `gpt-image-2` 出故事板 → Shuyu Seedance 2.5 出片**。
Runway 已下线。前端创作台继续给客户自助用，这条线路是我们自己把控质量的出片方式。

你是导演和编剧：提示词好不好由你负责，出图、出片之前都要自己确认过。

## 流程

一条视频一个任务目录 `tmp/director/<任务名>/`（`tmp` 不进仓库），里面放商品实拍图和你写的 `job.json`。

```bash
npm run director -- check  tmp/director/<任务名>                 # 校验脚本、打印提示词、按实时价目估算。不花钱
npm run director -- frames tmp/director/<任务名> --confirm-spend  # OpenAI 出故事板帧
npm run director -- select tmp/director/<任务名> --frame opening --variant 2
npm run director -- video  tmp/director/<任务名> --confirm-spend --max-points 2000
npm run director -- review tmp/director/<任务名>                 # 按镜头抽帧 + 静音段 + 片尾检查。不花钱
npm run director -- post   tmp/director/<任务名>                 # 本地后期：切条、烧字幕、片尾落款。不花点数
npm run director -- status tmp/director/<任务名>
```

1. **看素材。** 逐张看商品实拍图（Read 图片），弄清结构、材质、颜色、有没有 logo 和文字。没有实拍图就先向用户要，不凭空画商品。
   测试 / 样片例外：默认用毛毯类（2026-11-16 定，别再用保温瓶）。测试商品图在 `tmp/director/_assets/blanket/`（`hero.png` 整件、`detail.png` 面料细节）；
   没有了就照 `tmp/director/_assets/make-blanket-assets.ts` 的做法重出一套：先文生图出整件，再以整件为参考出细节。
2. **先想场景，再定片种，再写 `job.json`。** 场景决定拍什么（见「先想场景」），片种决定节奏。写之前用一句话说清这条片（`logline`）：说不清就还没想好。
3. **`check`，直到零错误。** 提醒逐条看，认了才往下走。把拼好的出片提示词通读一遍：一个没看过素材的人照着它拍，会不会拍错？
4. **`frames`，然后逐张看图。** 这是抽卡的地方（一张图几美分，一条片 1,500 点）。不合格就改提示词或 `--more 1` 再抽，合格才 `select`。
5. **`video`。** 先不带 `--confirm-spend` 看估算，再带上限提交。
6. **`review`，然后逐张看抽帧。** 每个镜头一行，第一帧紧贴切点（露脸、走样常常只出现在切进来的头几帧）。
   按下面的验收单过一遍，再向用户交付或说明为什么重拍。
7. **`post`（要字幕或落款时）。** 字幕、品牌名、行动指引由合成器直接烧上去，不经过视频模型，所以不会乱码。做完再 `review --file <后期后的文件>` 看一眼。

`frames` 和 `video` 都能随时中断重跑：进度在 `state.json`，有任务号的只续查、不重提。

## 先想场景

客户给的往往只有商品原图。片子要拍的不是这件商品摆在那里，而是**谁在什么时刻用它**（2026-11-16 CEO 定的方向：
口水巾第一版拍成了水滴测试 + 三色展示的商品演示，CEO 要的是家里、妈妈喂饭、宝宝戴着它、漏了接住、顺手一擦）。

动笔之前先填这张卡，填不出来就先去查同类商品的短片是怎么拍的（搜两三次就够，看的是开头用什么动作、拍的是哪个生活瞬间）：

| | 要回答的问题 | 口水巾的例子 |
|---|---|---|
| 谁用 | 用的人和买的人各是谁 | 六个月到一岁的宝宝用，妈妈买 |
| 在哪 | 最常用到它的地方 | 家里的餐椅上 |
| 哪个时刻 | 没有它最狼狈的那一下 | 喂辅食，喂一口漏半口 |
| 麻烦 | 这一下看得见的后果 | 米糊顺着下巴掉到衣服上，一天换好几身 |
| 用了之后 | 同一个时刻，看得见的不同 | 米糊落在口水巾上，衣服是干净的；拿它顺手一擦 |
| 情绪 | 结尾留给谁的表情 | 宝宝笑，妈妈省心 |

- **钩子从「麻烦」那一下来**：一个动作，不是对着镜头说话。看的人一眼认出这是自己家每天的事。
- **商品在场景里干活**，不是被摆出来展示。纯展示只留给最后的定格镜头。
- **该露脸就露脸**（2026-11-16 定）：婴儿用品、或者任何靠人的表情打动人的商品，情绪镜头大胆给正脸，两三个镜头都可以。
  Shuyu 同一款口水巾的片里宝宝正脸大笑出现了三个镜头，是全片最抓人的地方；我们第二条毛毯片里模型自己给的正脸也没出问题。
  写法见下面「人的脸」那一条。配角（喂饭的妈妈、递东西的人）仍然只出手和袖子：少一张脸，少一处前后不一致。
- 同一个商品可以有几个场景（喂饭、长牙流口水、出门推车里）：一条片只拍一个，其余的留给下一条。

## 商品类型卡

场景卡之前先定类型，写进 `job.json` 的 `productType`（不写 `check` 会提醒）。**真机只验证过第一行**（毛毯三条、口水巾三条）；
其余各行是按出片模型的一般表现推的，11-16 一位没参与过的审阅者逐类过了一遍，拍过一条才算数，拍完回来改这张表。

| 类型 `productType` | 好用的钩子 | 证明镜头 | 别拍 | 字 / 脸 | 要客户给的图 |
|---|---|---|---|---|---|
| 软品 `soft`（毯、巾、抱枕） | 触感、麻烦那一下 | 手按下去 / 吸水 | 远景里看小标签 | 小字去掉；配角不露脸 | 整件 + 面料特写 |
| 带印刷的硬品 `printed-hard`（瓶、罐、盒装） | 结果先行、光扫过 | 机位不动的正面，手握在标签以下 | 旋转、拧盖、标签微距 | 大字正对镜头，小字不给特写 | 正面、背面、标签特写 |
| 电子 `electronics` | 麻烦的场景 | 一个物理动作（开盒、戴上） | 亮屏内容、指示灯特写 | 屏幕熄灭，界面截图走后期 | 各面 + 熄屏图 |
| 服装鞋 `apparel` | 上身那一下 | 颈部以下 / 脚部走动 | 多个镜头的全身正脸 | 印花要特写参考；脸只在必要时 | 平铺 + 上身图 |
| 美妆护肤 `beauty` | 质地微距 | 手臂试色 / 滴落 | 上脸、功效前后对比 | 瓶身同硬品；默认不上脸 | 瓶身 + 质地色卡 |
| 食品饮料 `food` | 热气、倒入 | 2–3 秒机位不动的倒 / 滋响 | 咬、切开、跨镜头的液面 | 包装同硬品 | 包装 + 成品 |
| 大件 / 窗饰 `large` | 空间前后 | 一个机构动作，机位不动 | 换房间、微距 | 全片一个场景 | 客户房间图 + 尺寸 |
| 反光 / 透明 / 表 `reflective` | 光划过 | 商品不动、光动 | 环绕、微距表盘 | 表盘上的字只给中景 | 无反光的正面 + 佩戴图 |
| 过程型工具 `process`（清洁、厨具） | 麻烦的特写 | 一镜到底 4–6 秒（标 `"proof": true`） | 把过程切碎 | — | 工具 + 使用前的场景 |
| 宠物 `pet` | 宠物的反应 | 同一个镜头里的互动 | 跨镜头换角度拍宠物 | 宠物可以露脸 | 商品 + 宠物照 |

- 软件、服务这类没有实物的商品，这条线路不接：要拍的是人和处境，界面只能用真实录屏在后期加。
- `check` 会按类型查最常见的翻车写法（硬品旋转拧盖、电子亮屏、食品咬切、反光品环绕微距、过程型没标证明镜头）。
- 快销片「镜头越多越好」对硬品不成立：每次硬切商品都重新生成一遍，切得越多越容易走样。硬品用 5 个镜头，软品可以 6–7 个。
- 测试素材的局限：毛毯的「实拍图」其实是文生图出的，评测集十个品类的图也是 AI 出的、故意不带字。
  **带真实印刷文字的商品，我们一条都没拍过**，接到第一个这样的客户要先花一条 5 秒的钱试。

## 先定片种

第一条毛毯片的教训（2026-11-16）：用户要的是快销广告，交出去的是暖色调、慢动作、四个长镜头的生活方式片。商品和台词都对，节奏错了。

| | 快销广告 `fmcg` | 生活方式片 `lifestyle` |
|---|---|---|
| 目的 | 三秒内留住人，讲清卖点，催下单 | 营造向往的氛围 |
| 结构 | 钩子（≤2 秒）→ 2–3 个卖点（每个一个镜头）→ 使用场景 → 商品定格 + 行动指引 | 首态 → 一两个舒展的动作 → 定格 |
| 镜头 | 15 秒 5–7 个，每个 1–3 秒，硬切 | 15 秒 2–4 个，每个 3–6 秒 |
| 钩子 | 镜头 1 直接放最抓人的那一下：触感、前后对比、结果。不铺垫 | 可以从安静的首态开始 |
| 画面 | 明亮干净的光，特写多，商品占画面大 | 可以暗、可以暖、可以留白 |
| 口播 | 短句、带劲、每句一个卖点，最后一句是行动指引 | 一两句，慢 |
| 配乐 | 有节拍，切点跟拍子 | 铺底即可 |
| 运镜 | 快而稳（fast but controlled），慢动作只留给一个镜头 | 慢推、慢移 |

`check` 会按片种查节奏：快销片钩子超过 2 秒、镜头数不够、单个镜头超过 4 秒、最后一个镜头不到 2 秒、没写配乐或口播都会提醒。

**快销片 15 秒的默认骨架**（Shuyu 自己的创作台用的也是六拍，可以照着起稿再改）：

| 秒 | 这一拍做什么 |
|---|---|
| 0–2 | 钩子：一下抓住人 |
| 2–5 | 商品亮相：是什么、长什么样 |
| 5–9 | 核心卖点：一个动作 → 一个看得见的结果 |
| 9–12 | 使用场景：谁在什么时候用 |
| 12–13 | 对比或佐证：一眼看懂的差别（可并进上一拍） |
| 13–15 | 商品定格 + 行动指引 |

- **30 秒的快销片**（特价档 5–30 秒同价）：12 个上下的镜头，每个 2–3 秒，骨架是 15 秒六拍再加第二、第三个卖点、一次换场景和第二个情绪镜头，
  最后仍然是商品定格。真正卡人的是提示词 4,800 字的硬上限：12 个镜头平均每个不到 300 字，后面的镜头只写必写的四项、每项一句，
  参考图的职责也写短。2026-11-17 第一条 30 秒口水巾片压到了 4,736 字。
- **钩子只管镜头 1**，先挑一种再写：触感测试（手按下去）、前后对比（用之前的麻烦 → 用之后）、结果先行（先给最好看的那一下）、
  一个出人意料的用法、直接提问。挑定了，开场帧就画这一下发生之前的瞬间。
- **一条片只证明一个核心卖点**，写成「动作 → 看得见的结果」：不写「吸水好」，写水滴落上去一秒被吸干、布面不留水痕。
  别的卖点一句口播带过。`logline` 里要点出这一个证明，时间线里要有一个镜头真的拍它。
- **最后一个镜头留给商品**：至少 2 秒，商品占满画面，焦点在商品上，停住不动；行动指引那句话落在这里。

商品片的通用规律，两种片种都适用：

- **材质写成「材质 + 质感」，再加一个看得出效果的互动。** 不写「很软」，写手按下去绒面陷到指根、松手慢慢回弹；不写「好看」，写布料顺着扶手垂下来、褶子自然。
- **商品镜头从环境走到细节，光要有来处。** 每盏灯说得出是窗、是台灯还是顶灯。
- **动作会威胁到手、logo、文字的时候，简化动作，让光去做变化。** 大幅度的动作最容易把商品弄走样。
- **一条片一种主运镜。** 前面是推，后面就别突然环绕。

## 写脚本的规矩

- **全程英文。** 台词例外：放在英文双引号里，写商家要的原文，模型会逐字念。
- **六项都要想，不必都写。** `action` 主体与表演、`framing` 构图、`camera` 摄影机、`sound` 声音每个镜头必写；
  `space` 空间与调度、`light` 光色镜头 1 必写，后面的镜头没变就不写（等于沿用），变了才写。
- **一拍一个主动作、一个机位意图。** 出现 then / after that 就该拆成两个镜头。
- **时间用整数秒，首尾相接，正好铺满。** 留空档模型会自己加戏，塞太满会多切或丢拍。
- **硬切写明白。** 镜头开头写 Hard cut；要特别的转场就写清触发时刻和做法。常见运镜（push、pull、pan、track、orbit、handheld）直接写名字，
  冷门的要写出看得见的效果（rack focus：什么变虚、什么变实）。写了镜头高度更稳（at sofa-seat height）。
- **只写「快」会乱。** 写 fast but controlled。又快又稳这类互相矛盾的要求别同时给。
- **首帧放在主动作发生之前。** 开场帧和 `openingState` 都不提前露出结果。
- **参考图各管一件事。** `role` 写清这张图管什么、不继承什么。参考图已经说清的，提示词里指过去就行，别再用文字描述一遍。
- **抽象形容词模型拍不出来。** beautiful、cinematic、premium、dynamic 这些词换成看得见的东西：光从哪来、材质怎么动、镜头在哪。
- **全程要求用正面描述写（`throughout`）。** 否定句模型只在字幕和声音上听话。不写 never show a face，
  写 only hands, arms and the back of the head are seen。「不要字幕、不要画面文字」脚本会自动加。
- **人的脸：出片时按文字生成，不放进故事板帧。**
  - 要露脸的镜头写 `face visible`，再写表情和视线（laughs with a clean chin, looking at mom off-camera），别让人直勾勾盯镜头说话。
  - 同一个人在几个镜头里露脸，就在 `throughout` 里把这个人描述一次（年龄、发色发型、衣服），每个露脸的镜头用同一个称呼（the baby）。
    没有身份参考图，长相仍可能有出入：露脸镜头之间隔着商品特写，比连着切更不容易看出来。
  - **哪种脸 Seedance 2.5 收、哪种不收**（2026-11-16 汇总；只有第一行是我们自己拍出来的）：

    | 脸从哪来 | 现状 | 依据 |
    |---|---|---|
    | 出片时按文字生成（成人、婴儿） | 可以，效果好 | 第二条毛毯片的成人、口水巾场景版的宝宝大笑、Shuyu 同款片的三个宝宝正脸镜头 |
    | 故事板帧里 AI 画的脸（开场帧、关键帧、分镜总览图） | **没有结论** | 10-29 带正脸的帧 5 条全被拦；Shuyu 创作台 11-16 把分镜图打码改成了可选。11-16 我们拿宝宝正脸的开场帧试过两次都没出成，但那段时间 Shuyu 整体出故障（不带脸的对照片也起不来），这次不算数，要等恢复后重测 |
    | 客户给的真人照片当参考 | 不确定，按受限处理 | 各家说法不一：有的平台连 AI 画的脸都当真人拦，有的网关说已放开。要用先有肖像授权，再拿一条 5 秒的试 |
    | 明星、公众人物、真实赛事与品牌形象 | 不做 | Shuyu 自己的红线也是这条 |

    所以默认做法不变：开场帧用手部、侧背、裁到鼻子以下或商品主体，脸交给出片时按文字生成。
    **判断「被内容挡了」之前先排除供应商故障**：Shuyu 出故障时的表现是第一次提交「任务起不来」、同键重投后「受理 → 失败 → 退点」，
    和内容被拒长得一样。先拿一条已知能过的素材当对照，对照也起不来就是故障，别急着改脚本、换参考图（11-16 在这上面白折腾了四次）。
  - 婴儿和儿童：衣着完整（连体衣、口水巾），场景是家里的日常（餐椅、爬行垫、推车），身边有大人的手在照看。
- **镜头里有人，就写清脸在哪，而且从这一镜第一帧起就成立。** 第二条毛毯片第 4 镜写的是「人藏在抖开的毯子后面」，
  模型先给了 0.3 秒正脸再把毯子举起来。写成 from behind / cropped below the chin / hands only，
  或者把遮挡写进这一镜的起始状态（the blanket already covers her from the first frame）。真要露脸就写 face visible 认下来。`check` 会提醒。
- **商品上本来没有的字和 logo，不要让模型凭提示词去画。** 提示词里写品牌名等于请它自己编字（8 月在 Seedance 2.0 上实锤）。
- **要 Logo 跟着商品走，就把它做成商品的一部分，从图上带进去**（2026-11-16 在 2.5 上试过一条 5 秒的，见下）：
  先让 `gpt-image-2` 把 Logo 做成布标 / 印花画在开场帧的商品上（把 Logo 图当参考带进去，逐张放大核对每个字），
  再把布标的特写单独当一张参考图，`throughout` 里写「标签始终和 image N 一样」，提示词里不出现品牌名。
  那一条的结果：手拿起、弯折、放下、镜头推近，圆形图案和四个汉字在清楚的帧里全对；快速运动时糊（正常的运动模糊）；
  **最小的那行英文被改了一个字母（MENGXIN → MENOXIN）**。所以布标上只留图形和大字，小字去掉；
  只验证过近景里的一次，戴在人身上的远景没试过。实物上没有这个标的话先问客户，别让买家收到货对不上。
- **跨镜头的状态不会自己延续。** 每次硬切都是按参考图重新生成：上一镜洒在口水巾上的米糊，下一镜可能凭空没了（口水巾场景版第 3 镜实锤）。
  污渍、液面、已经打开的盖子这类要延续的状态，在后面每个镜头的 `action` 里再写一遍（the puree stain still on the bib），
  或者把「弄脏 → 解决」放进同一个镜头拍完。
- **提示词紧凑。** 目标每秒不超过 240 字（15 秒约 3,600 字；六镜头的快销片压到 3,300 字上下就没有重复内容了），硬上限 4,800。超了就删重复的空间与光色、并镜头，不靠截断。

## 声音

- **口播的声音只描述一次**，写在 `voice`：语言、性别与年龄感、语气、收音感（close-mic）。
- **台词写在它被念出来的那个镜头的 `sound` 里**，一个镜头一句短的。中文每秒 3.5 个字从容、4.5 个字是上限，英文每秒 2.5 个词从容、3 个词是上限
  （切镜之后人声要等约四分之一秒才出来）；念不完 `check` 会提醒。没有台词的镜头 1.5–2.5 秒就够。
- **一条片一个说话的人。** 说话的时候别给这个人写点头、转身这类动作。
- **配乐写在 `music`**：风格、速度、乐器、走向。快销片的切点跟拍子。
- **音效对着画面写**：每个声音都对应一个看得见的东西（按下去的布料声、抖开的呼声），想卡点就写在对应镜头里。
- 最后一句台词别贴着片尾：给结尾留半秒以上，不然会被截断。

## 交付的默认样子（按客户）

2026-11-17 定。先看这条片是做给谁的，再决定后期加什么：

| 做给谁 | 交付 | `job.json` 里写 |
|---|---|---|
| **梦馨家纺**（用户或 CEO 说了是梦馨的商品 / 给梦馨的） | 带字幕 + 右上角 Logo | `"post": { "captions": true, "logo": "assets/mengxin/logo-horizontal.png" }` |
| 没说给谁（测试片、样片、别的客户） | 和以前一样：原片 + 带字幕版，不加 Logo | `"post": { "captions": true }` |

- **要 Logo 就默认放右上角**（`logoPosition` 缺省 `top-right`），全程挂着，大小和位置脚本定好了。白底的 Logo 图直接用，不用抠图。
- 梦馨的 Logo 在仓库里：`assets/mengxin/logo-horizontal.png`（横排，带中文名，角标用这张）、`logo-icon.png`（只有图形）。
  这两张是从截图里裁的，够角标用；要放大用得跟客户要原文件。
- 没人说要 Logo 的片不要自己加；别的客户要 Logo，问清用哪张图，放法照旧是右上角。
- Logo 只在后期叠，不写进提示词、不画进故事板帧：11-16 试过让它印在商品上跟着走，正反两面都冒出来，还有错字。
- 交付时两个文件都给：原片（`…-take1.mp4`）和成品（`…-take1-post.mp4`）。

## 不加预算的几样工具

都写在 `job.json` 里，`check` 会查。

- **关键帧 `video.keyframes`**：后面某个镜头容易走样（换了场景、商品摆法不对、要特定姿势）时，在 `frames` 里给它单独写一帧，
  再列 `{ "frame": "<帧 id>", "shot": 5 }`。它会排在实拍图之后、开场帧之前带给出片模型。一张图几美分，最多 4 张。
- **分镜总览图**：`frames` 里某一帧写 `"sheet": true`，脚本会把每个镜头的动作与构图自动拼成一张编号小格的总览图当参考
  （`prompt` 里只写每格都一样的东西：商品、场景、光）。Shuyu 自己的创作台就是只带这一张图出片。**我们这条线路上还没实测过**，
  第一次用要和不带的版本对比着看，留意成片里有没有出现格子线或编号。
- **分条交付 `cuts`**：特价档 5–30 秒同价。写 30 秒、`"cuts": [15]`，`post` 会切成两条 15 秒，单条成本减半；
  或者同一个商品拍两个不同的钩子做对比。切点必须在镜头交界上，每一条都要自成一条片（各有钩子、口播、商品定格）。
  30 秒的质量稳不稳还没测过。
- **本地后期 `post`**：

  ```json
  "post": { "captions": true, "logo": "assets/mengxin/logo-horizontal.png",
            "signoff": { "brandName": "暖窝家居", "cta": "点下方链接 今天带走" } }
  ```

  `logo` 是全程挂在右上角的角标；`signoff` 是片尾最后两秒压的品牌名和行动指引，两样互不相干，都可以不写。

  字幕默认按脚本里每句台词所在镜头的时间烧（没有语音识别时的估法：模型把话说早说晚，字幕就会偏）；
  OpenAI 项目开通 `whisper-1` 之后自动改成跟着人声走，`review` 还会把识别到的台词打出来对照。
  落款压在最后约两秒的真实画面上，一条至少 6 秒才压。价格、促销这类字也只走这里，不让模型画。
  抖音要带「AI生成」角标：`post --platform douyin`。成片会被合成器放大到 1080 宽，字更清楚，画面细节不会变多。
- **试别家模型**：`video --family any --plan <套餐 id>`，必须点名一档。MiniMax H3 768P 约是 Seedance 特价档的四分之一价，
  口播带货这类对画质不挑的片可以拿同一个脚本对比一条；别家模型不一定认我们这套提示词顺序，先看成片再定。

## 看故事板帧（定稿之前）

- 商品的结构、比例、颜色、材质和实拍图对得上，没有多出或少掉部件。
- 商品颜色没被场景光染偏（暖色台灯会把灰绿染成黄绿）：两张都合格时选颜色更贴近实拍图的那张。
- 商品上的文字、logo 没有乱码或变形。
- 没有清晰正脸（露脸留给出片时按文字生成）；手指数量和姿势正常。
- 构图给后面的动作留了空间，画面是首态，结果还没发生。
- 片种对得上：快销片的开场帧要亮、商品要大。成片的气质在这一帧就定了，暗的开场帧出不了明快的片。
- 没有画面内文字、水印、拼图边框。

有一项不过就不定稿。改提示词比多抽几张有用。

## 看成片（交付之前）

- 分辨率与时长：`video` 结束时会打印量出来的宽高、时长、有没有声音。
- **节奏对不对片种**：快销片数一下实际切了几个镜头，有没有哪一段拖。
- 商品从头到尾没有走样，颜色在暗处没有发白或偏色，动作按时间线发生，没有多出脚本外的情节。
- 每个镜头是不是脚本写的那个镜头（模型常把最后一个镜头拍回开场帧的样子）。
- 画面里没有死黑、大块空白这类废掉的区域。
- 没有脚本外的正脸：逐行看每个镜头的第一帧。脚本里写了露脸的镜头，看五官有没有变形、几个露脸镜头像不像同一个人。
- 台词：`review` 在有语音识别时会把识别到的话打出来对照；没有的时候你听不了，只能查音轨有没有在片尾被截断。**念得对不对请用户听**，汇报里要说明这一点。
- 最后一秒是 `endState`，不是动作中途。

向用户汇报时说清楚：用了哪一档、花了多少点、哪几项过了、哪里不满意。不满意就说不满意，并给出重拍打算改什么。重拍一次只改一个方向，不然分不清是哪一处起的作用。

## 花钱的规矩

- **出片默认 Seedance 2.5 · 720P**，按这条片的时长取最便宜的一档（15 秒是特价方案 113，1,500 点按条计；5 秒以下是按秒的 VIP 档更便宜）。
  1080P 是 420 点/秒，15 秒 6,300 点，11-16 定了不用；用户明确要才加 `--resolution 1080P`。
- **`video` 每次都要 `--confirm-spend --max-points <上限>`**，脚本会估算、比上限、比余额（留 7,000 点预留线），三关都过才提交。
- **真机花点要用户点头。** 第一次给某个商品出片、或者要重拍，先把估算告诉用户再提交。
- 当场被拒不扣点，脚本会自动换同分辨率的下一档；受理后失败会停下来等你看原因，不会自动再花一次。
- 故事板帧走 OpenAI 的余额，一次最多 8 张（`--max-images` 可改）。

## 边界与没验证的事

- 不碰数据库：脚本把 `DATABASE_URL` 换成了连不上的地址。成片要进成品库是另一件事，先问用户。
- 不用 demo 账号、不做 mock：这条线路只走真实供应商。
- 套餐与价目会漂移：以 `check` 当场打印的阶梯为准，不要照抄本文件里的数字。
- **开场帧只是近似。** Shuyu 没有给 Seedance 2.5 开首帧模式：从它自己前端的套餐表看（11-16），首帧 / 首尾帧模式只在
  Seedance 2.0 的两档和 Kling 3.0 上有，图片也没有逐张的角色字段，角色靠顺序和提示词里的 image N 来指。
  我们把开场帧排在最后并在提示词里说明，11-16 实测成片的第一个画面接近开场帧但不逐像素一致。
- **音频 / 视频参考还没接。** Shuyu 自己的前端在「全能参考」模式下另收参考视频（MP4，≤15 秒、≤8 MB）和参考音频（https 地址），
  Seedance 2.5 各收 10 个，带了就要先单独报价。那是它内部网关的字段（`inputVideos` / `inputAudios`），
  对外接口收不收、叫什么、怎么计价都没试过；要用先问 Shuyu，别拿真单去猜。
- 提示词规则里有一部分来自 Seedance 2.0 的经验或转述的官方 2.5 指南（2026-08 的快照），没有逐条在我们这条线路上验证过。
  成片和规则对不上时，以成片为准，并回来改这份文件。
