## 2. Runway 开户之后怎么接（按顺序做）

> ⚠️ 本地提交的任务由**线上**定时任务每分钟轮询推进（本地和线上共用生产库）。
> 线上没有 Runway key 时，轮询连续失败 3 次（约 3 分钟）就会把任务判成失败。
> 所以**第一步必须先在线上配 key**，但先不切线路。

1. **CEO 开户**：在 dev.runwayml.com 建组织、生成 API key、预充额度。
   - API 额度和网页订阅是两个钱包。
   - 1 credit = $0.01。Seedance 2.5 起价 $0.20 / 秒，15 秒一段大约 $3 起，1080p 更贵。
2. **线上只配 key**：在 Vercel Production 环境加 `RUNWAYML_API_SECRET`，重新部署。
   **不要**配 `VIDEO_CUSTOMER_ROUTE`，客户照旧走 Shuyu。
3. **本地先验**：在 `.env.local` 加 `RUNWAYML_API_SECRET` 和 `VIDEO_CUSTOMER_ROUTE=runway`，然后起本地服务（`.claude/launch.json` 的 `app`，端口 3000）。
   - 用 CEO 测试账号打开那条 NORDA 订单，点「重新生成」：同一张图、同一段描述 → 一键出故事板 → 确认 → 生成视频。
   - 对比 Shuyu 那条：每个镜头的 logo、时长、耗时，以及成本（Runway 控制台看 credits）。
   - Runway 的产出成功后会先转存到我们的 blob（`renders/provider-outputs/runway/`），再交给拼接。
4. **通过后切线路**：Vercel 加 `VIDEO_CUSTOMER_ROUTE=runway`，重新部署后做冒烟。要 1080p 再加 `RUNWAY_VIDEO_RESOLUTION=1080p`。
5. **回滚**：删掉 `VIDEO_CUSTOMER_ROUTE`，重新部署，客户就回到 Shuyu。key 可以留着。

**还没被真机验证的地方**（第一次跑重点看）：
- 请求字段是照官方 Node SDK 的类型写的。
- 故事板路径走 `text_to_video` + `references`，提示词里「image N」的序号默认和 references 的顺序一致（Shuyu 也是这个约定）。
- 产出地址能不能正常下载转存。
- THROTTLED（账户并发满了）时的排队表现。
- 1080p 下画面质检的表现。

不确定的地方先看 `src/lib/providers/runway.ts` 顶部注释，有出入就改那里。

## 5. 已知遗留

- 镜头卡 LLM 超时后请求不中止，要改全站共用的 AI 调用层，暂缓。
- 出方案用 sol 档，约 35 秒；派发时服务端还会再出一遍，约 40 秒。可以考虑把预览方案缓存到服务端复用，但要存储，暂不做。

- 本地开发的坑：
  - 浏览器面板隐藏时，成品库详情会停在「正在加载成品库…」，自动刷新也暂停。
